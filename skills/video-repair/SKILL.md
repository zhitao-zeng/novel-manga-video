description: Diagnose a failed video clip from source, requests, images, actual takes and review history, then propose a bounded final H3 request correction.
---

The host already decoded the videos. Start by reading the current take's JPEGs in evidence.takes[].frames; seconds are sample times within that take. Use `python3 tools/video_frames.py take-1` or `--seconds 2.0` to locate supplied frames. The time selector returns the nearest supplied sample, not a new exact-time extraction. Check each take's own request and ASR; reference cards are not actual generated footage. Do not use Read on MP4, install packages, probe system video libraries, or spend the repair window preparing tools. If images cannot support a decision, output stop with the precise missing evidence. Produce output/decision.json within this attempt even when blocked.

Read input/evidence.json and its primary_reading index. This task repairs one request within a600-second execution window. Start with the current frames, actual request, selected reference and inline target/neighbouring shots with their source facts. Historical takes, whole-episode source documents, interaction/overlay files and asset profiles are available for specific unresolved contradictions, not a mandatory reading list. Do not re-read an archived copy of the current render as if it were a prior generation. Once primary evidence supports edit, retake, keep or stop, write the final output immediately; do not spend the window exhausting auxiliary files. Use the shared request_rules supplied by the production compiler. Compare the actual picture with the intended shot; do not merely repeat the reviewer. A positive reference check is not proof of correct plot or object counts. Treat proposed generation causes as hypotheses unless supported by a direct input contradiction or controlled evidence; an omitted descriptive phrase alone does not prove why the model erred. Category changes can describe the same visible fault.

Return output/decision.json with action (edit, retake, keep, stop), reason, and evidence (a list of input file paths plus concise observations). For edit write output/decision.json and the complete final H3 English request in output/prompt.txt together in one tool turn, then finish. Replace conflicting text rather than appending the error description. Describe the target visible state concisely instead of listing every prior defect as a prohibition. Organize each shot as setup, its single bound utterance, and the meaningful result; do not narrate finishing speech before the dialogue or add a generic hold to fill time. Correct wearing versus independent objects, visibility and physically observable states using the source and actual references; do not invent a new scene. If the source itself is wrong and cannot be faithfully expressed, choose stop and explain the required source change.

Preserve the six H3 sections, subject/audio labels and their reference mappings, retention labels/modes, exact dialogue and speaker/audio bindings, shot count and timing. You may clarify identity/clothing/state descriptions in subject_definitions and retention_analysis using the reference evidence, and revise shot directions and audiovisual corrections, but not add dialogue, change story events or change the scene's factual order. Speech directions can specify when the existing utterance starts/stops and who stays silent; they are not new dialogue or a reason to invent visual content.

retake means the input is already correct and one new seed is justified. keep proposes a false-positive recheck; the pipeline must independently verify it. stop means there is no supported repair. Do not force an edit for every clip.

Only work on /work copies. Do not call generation services, modify budgets, publish or attempt to access production paths. The pipeline owns actual generation and its existing total-attempt cap. No automatic extra retry follows a rejected candidate. Do not infer electrical sound causes visible arcs: that hypothesis was not supported by the controlled examples.
