The host already decoded the videos. When primary.final_cut is present, first inspect its supplied final-cut JPEGs and verify the reported issues against actual pictures and source_basis. Those timestamps are global seconds in the reviewed final movie and include any relevant neighbouring clip boundary; do not substitute native-take frames for final-movie continuity or blindly turn a report into a fact. Missing or inconclusive final-cut evidence requires stop with the precise missing evidence, or keep for an independently verified false positive. For native findings, start by reading the current take's JPEGs in evidence.takes[].frames; their seconds are sample times within that take. Use `python3 tools/video_frames.py take-1` or `--seconds 2.0` to locate supplied native frames. The time selector returns the nearest supplied sample, not a new exact-time extraction. Check each take's own request and ASR; reference cards are not actual generated footage. Do not use Read on MP4, install packages, probe system video libraries, or spend the repair window preparing tools. If images cannot support a decision, output stop with the precise missing evidence. Produce output/decision.json within this attempt even when blocked.

Read input/primary.json first; input/evidence.json retains the full source and history. This task repairs one request within a 600-second execution window. Start with the current frames, actual request, selected reference and inline target/neighbouring shots with their source facts. Historical takes, whole-episode source documents, interaction/overlay files and asset profiles are available for specific unresolved contradictions, not a mandatory reading list. Do not re-read an archived copy of the current render as if it were a prior generation. Once primary evidence supports edit, retake, keep or stop, write the final output immediately; do not spend the window exhausting auxiliary files. Use the shared request_rules supplied by the production compiler. Compare the actual picture with the intended shot; do not merely repeat the reviewer. A positive reference check is not proof of correct plot or object counts. Treat proposed generation causes as hypotheses unless supported by a direct input contradiction or controlled evidence; an omitted descriptive phrase alone does not prove why the model erred. Category changes can describe the same visible fault.

Return output/decision.json with action (edit, retake, keep, stop), reason, and evidence (a list of input file paths plus concise observations). Read provider and request_field in input/primary.json. For edit write output/decision.json and the complete output/prompt.txt together in one tool turn, then finish: the final H3 English request for h3, or the existing compiled Chinese request for sd25. Never transfer H3 tags or section grammar into SD. Replace conflicting text rather than appending the error description. Describe the target visible state concisely instead of listing every prior defect as a prohibition. Organize each shot as setup, all ordered bound utterances and intervening actions, and the meaningful result; preserve every turn in a continuous conversation; do not narrate finishing speech before the dialogue or add a generic hold to fill time. Correct wearing versus independent objects, visibility and physically observable states using the source and actual references; do not invent a new scene. If the source itself is wrong and cannot be faithfully expressed, choose stop and explain the required source change.

For H3, preserve the six H3 sections, subject/audio labels and their reference mappings, retention labels/modes, exact dialogue and speaker/audio bindings, shot count and timing. You may clarify identity/clothing/state descriptions in subject_definitions and retention_analysis using the reference evidence, and revise shot directions and audiovisual corrections, but not add dialogue, change story events or change the scene's factual order. Speech directions can specify when the existing utterance starts/stops and who stays silent; they are not new dialogue or a reason to invent visual content.

For SD2.5, preserve every non-stage line exactly, including reference definitions, total duration and style. Preserve each stage header, its entire 声音： clause, all dialogue in braces and all @图片/@音频 tags. Only clarify visible actions within the existing stage lines using retained source and image evidence. If the necessary fix requires changing a protected binding or source fact, stop and identify it; do not disguise a source correction as a prompt edit.

retake means the input is already correct and one new seed is justified. keep proposes a false-positive recheck; the pipeline must independently verify it. stop means there is no supported repair. Do not force an edit for every clip.

Only work on /work copies. Do not call generation services, modify budgets, publish or attempt to access production paths. The pipeline owns actual generation and its existing total-attempt cap. Produce one candidate per invocation. Only when the host explicitly returns a rejected candidate in primary.rejections may you revise it using the exact rejection reason, check evidence and input/rejected-candidate-N.txt file. The host permits at most three candidates including the first; each invocation retains its 600-second window and all original video limits. Correct the rejected request without changing protected source, dialogue, bindings or timing. If a compliant repair requires a source change, choose stop. Never retry autonomously or reinterpret service failures or exhausted budgets as permission for another candidate. Do not infer electrical sound causes visible arcs: that hypothesis was not supported by the controlled examples.

Identity portraits constrain only visible design. Do not infer hidden clothes/equipment are absent or replace current-phase wardrobe with an old full-body description. Check actual visible contradictions and current source facts.
