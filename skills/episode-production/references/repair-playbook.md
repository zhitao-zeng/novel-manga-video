# Repair playbook

Use the current task's targets, evidence files and exact operation permissions.
The host owns routing, retry limits, resource waits, accounting and acceptance.
Historical cases explain observations, not new permissions. Consult the
[output contract](output-contract.md) for payloads and [case evidence](case-lessons.md)
only when a recorded cause matches.

## Find the first wrong artifact

Compare original passage → adopted shots → selected references → submitted request
→ selected take → assembled movie. Start with the target's evidence_file; consult
wider context when identity, dialogue or continuity depends on adjacent shots.
Missing evidence, execution failure and confirmed content defects are different.
An empty/truncated judge reply is an unfinished check, not a reason to rewrite content.

| Evidence | Next action |
| --- | --- |
| Wrong speaker, identity, event or private/public delivery in the script | Use source-backed input repair for the owner, turns, actions and affected adjacent states. Keep valid words/cuts and source trace. Shared body type or similar names alone do not establish one identity. |
| Source/request and selected reference disagree | Correct the earliest binding or source-backed asset/phase. Existing actors use phases; missing actors use characters; settings use locations. Preserve animal, object and wearing roles. Never change the story because another image is available. |
| Missing or malformed final English | Repair the request through the existing contract, preserving dialogue slots, reference order and duration. A format defect alone does not require a new screenplay. |
| Missing or incorrect speech | Compare actual audio, raw ASR and bound words. Compress overfull dialogue into natural causal turns, preserving key commands and decisions; update obsolete actions and sound cues together. Use supported splitting when needed. Recheck homophones/nonverbal laughter; missing commands or extra intelligible speech remain defects. |
| A visible defect can be removed at the edge while preserving the story | Use the offered crop action for a fixed close view, keeping the required actors, actions and original audio. The host reviews the resulting take before finish; a crop receipt is not acceptance. |
| Video exists but analysis is missing | Continue the same take's analysis/assembly handoff. Do not invent empty chunks or regenerate solely for a missing report. |
| Wrong/missing/duplicated person, broken body or proportions, wrong action or severe instability | Inspect ordered frames beside actual references; distinguish perspective and folded limbs from persistent anatomical distortion. Count physical instances, not identity names. Compare raw take and final movie to locate generation versus postprocessing faults. Repair the implicated request/asset or use a permitted retake, then inspect the new result. |
| Minor wardrobe/background/pose differences | Apply the current task's delivery policy: a pose mismatch needs a concrete change in the event or character's situation to block delivery. An allowed warning does not clear independent speech, identity, body distortion, action or technical failures. Do not spend new takes chasing an allowed cosmetic difference. |
| Network, CLI/context, configuration or service failure | Preserve candidate/completed assets; report the execution error for the host's technical retry/resume route. An idle summary is not a provider failure, and a failed call does not judge story content. |
| H3 has a task ID or unknown submission outcome | Resume/query that exact task. Client timeout does not prove server rejection. Preserve the receipt; a new attempt directory must not submit a duplicate. |

## Execute and retain partial work

Write the candidate, check it, then apply/adopt/render as offered by the host.
Check validates its stated scope; an accepted job means submission. Inspect its
completed changed/accepted/blocked results. One failed clip does not erase another
clip's successful operation. A yielded job is already submitted: end the turn
and resume from its returned result instead of polling or submitting again.

resume:true continues the unchanged saved proposal. Changed fields belong to a
new or permitted revised proposal. Use an offered resume_action to reuse images
and completed steps. Repair genuine shared-shot dependencies together; do not
repack or narrow scope to obtain fresh budgets. When the candidate is ready,
continue its remaining media operation instead of repeatedly applying it.
The host prepares registered missing reference cards before compilation and refreshes
the adopted shot addresses after replanning. Read the current input snapshot;
missing files or an old shot address are execution problems, not story defects.

After the job completes, unresolved_clips (legacy pending) are remaining targets,
not background jobs. Choose a currently allowed action. Report the particular
action lacking permission: time, input revisions and video takes are separate.
A context refresh or a different error name renews none of them.

## Reuse evidence and record outcomes

related_history contains summaries and evidence_file links to actual saved
operations. Adapt relevant changes to current facts using current permissions.
changed proves an operation was applied; accepted_clip proves that recorded clip
passed recheck. Neither proves every earlier remedy worked or a new take passed.
not_recorded supplies no reproducible recipe. Unresolved cases are negative evidence.

The host retains decisions, per-operation issues and outcomes, including early
repairs followed by later checks. Source quotes, changed fields and reasons must
reflect the actual action. Generated/assembled/published is not formal acceptance.
Finish through the existing host result; do not overwrite failures or incomplete
checks to make a case appear successful.
