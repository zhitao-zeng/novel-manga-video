# 流程收敛：审核复用、局部修复和交付

本轮沿现有 `EpisodeBridge → finish → delivery` 接线，保留原 Agent、审查、预算和生成历史。未修改模型路由或批量恢复额度，未重跑已完成的 800 集。

## 已修改

- 宿主等待使用 `EpisodeBridge.operation_status()` 读取已有 future。只有任务结束才读取一次完整集状态；Agent 主动查询 `status` 的返回和交接语义保持原样。任务失败仍返回原错误。
- `finish` 把当前合成报告中的封面随视频复制到同一个 `final-candidate`，在现有 manifest/工具回执中返回对应路径。不增加内容审核；没有封面的旧收尾不能据此宣称完整远端交付。
- 正常单集入口在正式通过后，可按书目录的 `modelscope_delivery.json` 调用共用上传入口。上传失败保留正式验收和计数，只记录交付待续；重新执行正常入口会复用已经完成的生产结果。持续服务故障仍会报告待续，不宣称已上传。
- 上传只包含本集视频、对应封面和 `all-episodes.json`。保留旧播放地址和其他集条目，合并仍对应当前版本的已验证回执，避免旧索引回写覆盖先前交付。远端视频/封面大小和索引逐条回读通过才写完成回执。相同版本不重传；仅补封面不重传视频。SDK 和原 `util.retry` 处理续传及有限重试，读取索引的传播等待不会重复发送媒体。

目标数据集须已存在，凭据由原 SDK 安全存储读取。按书明确设置目标，不在全局默认上传其他书：

```json
{
  "repository": "owner/book-episodes",
  "python": "/path/to/python-with-modelscope-hub"
}
```

只续交付、不启动模型或生成：

```bash
PYTHONPATH=/path/to/novel-manga-video/src /path/to/python-with-modelscope-hub \
  -m novel_manga.application.production.modelscope_delivery \
  --novel-dir /path/to/book --run-dir /path/to/accepted-run \
  --episode 7 --repository owner/book-episodes
```

上传子进程独立直连，宿主模型及内网服务的代理环境不变。远端操作回执在 `run_dir/delivery/modelscope.json`；书级已验证交付放在 `book/delivery/modelscope/`。公开索引不添加“待审版”等操作说明。

## 第二批：复用审核和统一可看标准

将此前本会话已生产验证的修复收回现有入口：原生审核的派生标签不再使同一成片失效；仅本集相关人物、道具和场景进入圣经上下文。完整当前选片只需重新合成，不能用旧成片的问题指导新选片。版本绑定复用已有 plan/H3/take 标识，包含实际 postmix 选片，不创建第二套指纹。

整片分组中断后复用同证据下已经有效完成的组，失败结论也一并保留；影片、字幕或实际依赖变化时不复用。独立审查、争议和普通整片共用证据比较，审核标签变化不会重新发放一次争议机会。整片/独立审核获得已有 ASR 和语音门证据，不以计划对白冒充实际音频。没有增加审核层。

共享 `WATCHABLE_CRITERIA` 收回已实测的 v1.25：合理改编、普通服饰和非关键动作差异只提示；关键错人、对白错漏/反义、动作归属、严重身体错误与抖动仍阻断。相同模式、实际 take 和依赖不变的 v1.24 有效 pass/minor 可复用；旧失败不自动通过。已有当前整片有效通过时，可判断局部外观/状态差异是否影响剧情，不能覆盖明确的其他独立缺陷。这些均来源于已验证修复，不引入新故障额度或全局跳审开关。

358/473/648/739 四份真实上下文的圣经部分分别从 310035/596262/597465/596262 字符减到 8825/14984/14446/15177 字符；这仅是资料体积，不是已实测节省的计费 token。四份实际 assembly_inputs 均匹配当前选片，构造的缺片仍被拒绝。分组中断回归证明同一任务重启后只审未完成组，同时保留先前错人失败；真实内容判官准确性仍须与后续实际任务区分。

## 第三批：Agent 局部修复与自动收尾

`crop` 接在原来的 check/apply 上：对有待解决问题的现有 take 给出归一化 x/y/width，按制作比例取固定近景；保留原视频、音轨、ASR 和请求。同一源片与裁切复用原产物，不叠加裁切。第一遍生产仍只补缺片输入，不能提前修已有影片；裁切也不刷新原 Agent 时间、提案或 H3 额度。

宿主接回裁切结果后调用原 review。当前片段通过后合成、技术 QC，再由原 finish 收尾，不为点击下一步再开一次 Agent。新派生片仍需真实内容检查，不能靠裁切回执通过；未解决问题继续反馈给原 Agent。repair memory 保存实际裁切操作和结果，Skill 的输出协议/修复手册同步，版本更新为 2026-10-20。过载对白的指导也归入原修复条目：用自然短句保留关键因果、命令和决定，并同步清理过时动作/音效，不逐字硬塞 15 秒。

648 证明过的“完整 ASR 但缺 native.wav”通过同 take analyser 补回波形，复用既有 ASR，不重拍。H3 远程 API 与本地实例使用相同英文请求识别、缓存校验和未知任务保护；修正的是已选 H3 后端的请求交接，没有切换 LLM 或视频模型，也没有带入非 H3 的额外额度激活放宽。

普通新集完成分段人物/剧情/对白检查和最终技术 QC 即可收尾。已登记独立审查、有整片报告的在审任务、显式整片审查请求继续完成；后期交付 receipt 触发跨镜/字幕审查。有效整片失败不会因默认改为按需而消失；显式授权跳过在内部记录 skipped_by_user，未要求则记录 not_required，均不写 whole passed。明确要求但没有有效结果仍不能 finish 或发布。原始媒体、审查与授权记录保留。

finish 在同份 manifest 记录实际 episode_status，交付入口要求 manifest passed、quality_review passed、episode_status done 三项齐全，随后核视频、封面和远端索引。旧 finish 缺少封面/正式状态的交付包应由当前 finish 补齐，不能伪造字段。

473 的旧原片经新入口在隔离目录生成近景，9.227 秒，提取的 AAC 音频数据与原片逐字节一致；再次提交复用结果，原生成计数完整保持。没有 H3/LLM/ASR 调用、生产写入或新上传。这次仅验证候选生成与复用，不将历史人工 AI 判断冒充此次新的内容验收。自动 check/apply→review→finish 链及错人/漏对白/未完成的拒绝由集成回归覆盖，后续真实新集的费用与质量仍按真实调用账本统计。

运行证据：`crop-real-473/result.json`、`release-tests.xml`、`release-integration-tests.xml`。临时逐集驱动、故障补额分支和手工通过记录只留作历史；不进入新的默认 Agent。全局模型配置、旧计数和其他会话工作保持原样。
