# 身份修正接入生产（2026-10-09）

前一轮光明台账修订是一次有原文依据的数据操作。它清掉了当时的错误，但不等于以后读书与规划能自动做同样的事。本轮将语义核对、一次修订和写回前复核接到两个现有入口。

## 实际调用链

书级读书：`planning/reading.main` 或 `identity/ledger_flow.run_resolve` → `identity/ledger_resolution.resolve_chapter` → 原解析、归属判定与合并 → `identity/semantic_review.book`。复核读取本章完整原文、相邻章、候选涉及实体的首次建档章（有该来源时）、原始档案、人工确认及最终内存候选。

有错误时模型返回原结构的修订。流程恢复修改前的内存，再解析这份修订，复核实际解析结果。批准之后才写章节指称、关系、正式台账和两个索引，最后在既有 raw 文件记批准依据。最多一次修订；第二次复核仍不通过或模型返回非法引用时，恢复内存并报错。原始抽取缓存可以保留，不充当已落账结果。

章节绑定：`planning/cast_inputs.prepare_cast`、准备审查及局部修复 → `identity/flow.resolve_chapter` → 独立原文主体抽取 → 原候选检索 → `semantic_review.bindings` → 明确绑定 → 既有 `identity_context.json`。Agent 的正常准备调用相同 preparation/planning 路径；已有视频任务仍遵从原续跑机制，不强制重编已拍计划。

绑定决定区分已有实体、临时演员/群体/物件、库里遗漏的明确姓名及真正无法判断的归属。批准的临时主体通过既有 `extras` 和匿名说话人菜单进入规划；不会为它强造姓名或永久卡。明确的新姓名才进入现有 reading_cast/entity 台账和后续人物库增长。模型修改人数、类型或在场状态后，下游消费这份已核结果；原身体区分检查若会推翻绑定，在写回前报告矛盾。

## 续跑与失败

- 每个入口正常新增一次语义核对；发现错误后新增一次最终复核。原抽取、关系判官、补建和传输层重试仍存在，不能把整个章节总调用数说成最多两次。
- 保留书级写锁和既有模型资源槽。复核只操作候选，未批准不写正式台账或新姓名，不消耗视频生成次数。
- 书级复核失败时，本章人物库增长延期，其他章节继续，命令返回未完成状态。不会再从另一份名称扫描或旧章节记录补建这一章。
- 原文、相关实体、人工决定及对应关系不变时可复用已批准结果；无关实体新增和纯外貌设计更新不强制重查。
- 章节身份版本升为 v7。旧 v5/v6 的原文抽取可复用，但旧绑定不能直接充当新复核通过。没有语义批准的书级旧落账也进入正常读书续跑范围。
- 人工 corrections 原文件与决定仍保留；自动流程不覆盖确认。真正有歧义的归属仍由原准备失败/Agent恢复机制处理，不凭相似姓名猜人。

## 验证和实际限制

跨入口回归直接运行真实解析、绑定和写回函数，只模拟模型响应，覆盖错 ID、错误别名、匿名演员下游交接、新姓名补建、非法引用、不同身体误合、旧缓存更新、相关身份变更及失败章不建档而其他章继续。其他现有单元测试隔离新增模型服务；它们不证明语义判官准确率。

真实文字请求使用当前健康的 DeepSeek 接口，在独立最小书目录运行。书级错误有效 ID 和章节错误别名均自动改回正确实体；单一无名少女自动确定为临时演员。FlashNext 当时连接失败，仅验证进程选用 DeepSeek，生产配置和服务没有改动。回执位于 `.runtime/identity-auto-closure-20261009/verified-results.json`。

并非所有真实样本都通过：带父亲/叔父的样本中模型扩大修订范围并补出不适当关系；三名侍女的群体样本把群体与成员重复登记；另一个匿名样本返回的演员与绑定名单不一致。这些均未获最终批准，失败留在实验目录。本轮收窄修订范围和补齐绑定协议，但没有把模型语义质量当成已解决，也没有增加群体成员持久化结构。

本次没有全书重建历史人物库、重画卡片、重拍视频或改在产快照。孤立标签的全书来源追查仍不是新建的后台流程；本轮自动闭环处理实际进入现有读书和章节准备的资料。

独立工作树完整测试通过，新增闭环回归 13 项。冻结用例只更新身份版本号和批准结果元数据；原生成请求内容、修段策略和写入格式的其他部分保持原对照。合并版本的检查结果随交付回执记录。
