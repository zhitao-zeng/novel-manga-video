# 共享模型调用与审查拆分 · 2026-09-16

本轮将模型连接与审查职责分开。保留已有提示词、模式、判定标准、超时与重试、证据优先级、片段版本识别、报告字段及缓存复用方式。不启动真实模型请求，不重规划、重拍或修正历史人物资料；诸天继续暂停。

## 职责与调用

| 所有者 | 职责 |
|---|---|
| `model_client.py` | 图片输入编码、JSON schema 辅助、端点顺序、凭据读取、流式返回拼接、JSON 请求、同一超时预算中的原重试。 |
| `review/contracts.py` | 原审查字段、固定问题、阈值及 policy 版本。`thin_runs` 引用同一版本，历史缓存继续有效。 |
| `review/evidence.py` | 本次片段的内存证据对象 `ClipEvidence`，不新增落盘格式。 |
| `review/prompts.py` | 用显式证据构造普通审查和精判文字，不读取文件或调用模型。 |
| `review/policy.py` | 原判词到 must_fix / optional / ignore 的解释、反馈和精判结果转换，不派单。 |
| `review/storage.py` | 原 inode / size / mtime 片段版本识别，供审查与修复历史共用。 |
| `story/name_rules.py` | 人物库扫描与账本原来共用的泛称排除规则，未增加词条。 |
| `scripts/review_evidence_thin.py` | 原文、账本、身份与成长阶段证据读取，角色卡和视频帧选择。 |
| `scripts/review_judges_thin.py` | 组装一次审查请求，调用共享客户端，返回原结构；包括原文核对及修正指令请求。 |
| `scripts/review_episode_thin.py` | 读取本集、选择素材、复用同版本结论、逐段容错、生成并写回报告。 |
| `scripts/review_cards_thin.py` | 卡片审查报告和原有一次性资产修正；地点卡策略显式传入。 |
| `scripts/review_bible_thin.py` | 原有人物和地点扫描、补全、加锁写回、卷梗概。未改变人物库生成策略。 |
| `scripts/thin_review.py` | 保留 bible / cards / episode / volume / grow 命令与参数，共 46 行。 |

依赖方向为：命令/编排 → 取证与模型评审 → 共享提示词、判词规则和客户端。

所有 Python 内部调用方已改为引用职责所属模块。规划、身份核对、账本和 H3 提示词编译不再从 `thin_review` 借模型工具；修复历史不再为获取素材版本识别导入完整审查入口。共享模块不导入生产脚本，未增加旧工具的兼容导出层。

管理复审仍沿用 `repair_review_thin`、`verify_clips_thin` 与 shared audit 的队列、锁、确认顺序和写回方式；本轮只是将它们用到的共享能力接到新位置，不重写调度器。

## 行为对照与验收

- 整理前（`e6e8093`）冻结 11 组完整模型输入：普通审查/精判分别覆盖群聊插卡和画内聊天、临时动物、听者、画外台词、背景人物；另含人物/地点提取、两类卡片检查、原文核对、修正指令、卷梗概。
- 整理后图片编码、完整提示词、schema、请求名称与 token 上限逐项一致。冻结数据和可重复测试在 `tests/fixtures/review_requests_before.json`、`tests/test_review_contract.py`。
- 测试覆盖流式 usage、空响应与服务端错误、原有端点切换条件、截断次数和剩余超时预算；保持客户端原规则。
- 普通与精判提示词重复构造一致，输入不被修改。
- 同版本素材复用审查结论；失败只记录本段，下一次只补失败段；旧版本精判不清除新版本问题；Flash 候选仍需原确认步骤，技术错误不被语义通过清除。后几项复用既有修复回归。
- 原直接命令在定义精判函数之前就执行 `main()`，episode 分支会遇到尚未定义的 `review_mode`。拆分后入口先导入完整模块再执行，补了直接运行 episode 精判的回归；未改变问题或判定标准。
- 独立导出的提交版本完整测试 799 项通过，保留其他本地改动的工作树 801 项通过；模型使用模拟返回，没有访问实际模型服务。测试包含既有媒体 FFmpeg 回归。

本机完整前后对照和测试日志保存在 `outputs/review-decoupling-20260916/`（不进入 Git）。

## 后续边界

- 规划器的完整生成请求仍保留独有参数与预算策略；本轮共享传输工具，没有强行合并为审查请求。
- 审查的 Qwen 模型/环境仍按原规则每进程选定；精判执行器仍在请求前恢复自己的端点配置。本轮没有引入同进程混合不同判官的新运行方式。
- 普通判词的 `BREAKDOWN` 与 `ENTITY_TIERS` 仍保留原进程级状态；默认类别缺少 breakdown_pattern 时不会重置前一类别的模式。后续若支持一个进程交错评审多本书，应单独改为显式上下文并验证判定变化。
- 修复复审、历史发布、补查队列与批量编排之间尚有互相引用，应另开范围拆分；不是这次已消除的耦合。
