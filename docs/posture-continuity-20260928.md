# 姿态台账的连续性边界（2026-09-28）

本次接入的是剧本姿态台账，记录计划要求的坐站与位置，不把它称为成片已实现的状态。原人物身份台账、穿戴关系与面罩状态表继续各自负责原职责。

## 修正内容

旧 `claude/posture-ledger` 实验按 `scene_id`、缺失时按地点把相邻镜头分组。因此“昨夜坐在诊室 → 次日仍在诊室”会错误延续坐姿。旧实现还用全镜动作关键词判断某个人是否发生合理姿态变化，另一个人的“站起”也可能使矛盾不再被报告。该实验工作树原样保留，本次未整批导入其其他改动。

现在由一次结构化读取同时判断：

- 本镜与前镜是否连续、重置或不明确，依据包含原文、时间、场景描述与动作交接。地点或场景编号相同不能证明时间连续。
- 对每个人分别判断承接、首次/重新入场或不明确。空镜或反打不等于离场；重新进入同一房间也不能自动回到原来的椅子上。
- 先记录本镜的原句依据，再分类起点与末态姿势。没写就是未写明，程序仅在已经确认连续时继承，并记录 `inherited_from`。

程序不读动作关键词猜姿态，也不编写起身、坐下。明确的跳时和重新入场清掉瞬时状态；连续性不明、无依据的坐站变化进入原有规划补丁。位置使用场景锚点，不把前景、画面左右作为可以跨机位继承的位置。

回复漏镜、重复镜号、错误人物或不存在的姿态引用会要求模型修正一次；第二次仍无有效回复则失败。多个错误引用一起反馈。只有需要解释坐站变化时才核对动作引用，“端杯子”等普通动作不会单独变成姿态门槛。

## 实际接入

- 新规划：结构检查通过后读取台账，姿态问题进入现有 `patch_plan` 循环，只有接受的剧本才同时写入 `posture_states.json`。离线 `--replay` 不新增模型调用。
- 打包：读取当前台账，仅为未写明而合法继承的起点补充姿态。已经写明的姿态不再追加一遍。台账与当前剧本/原文不一致时拒绝沿用；打包本身不请求模型。
- 修复：候选剧本先在内存重新解析台账，重编受影响镜头与真正依赖它的后续镜头。下一场不受前场变更影响。候选未通过时，原剧本、计划、台账和生成次数不变；接受后按原写回流程一起保存。
- 缓存：未变化的输入复用已保存的模型回复；前镜、时间或原文变化时重新读取相关批次。这里只保存输入内容并比较，不新加哈希。无修改的修复保留中文、英文请求和旧缓存。
- 历史拆段：一个镜头内部姿态发生变化时，后续拆分片段不会再次附加开场姿态；已有切分范围和对白归属保持。

纯继承规则位于 `story/posture.py`；模型及文件读取位于 `application/packing/posture.py`；规划诊断接在 `application/planning/posture.py`。没有新增队列、进程或视频生成入口。

历史剧本不会因代码更新自动重拍。需要补台账时使用：

```bash
PYTHONPATH=src .venv/bin/python scripts/fill_posture_states.py --episode-dir <集目录>
```

这条命令只写台账并报告问题，不打包、不生成。无问题后，原有打包/修复流程才可使用它。有问题则先修剧本；不能把台账存在当作通过。

## 验证记录

回归覆盖同地点次日、回忆切入切出、反打与空镜、角色重新入场、他人动作不能替本人的姿态变化作证、上游修改使继承失效、模型证据错误的有界修正，以及规划补丁、中文打包、H3 翻译输入、修复写回和缓存。

真实本地 Qwen 的六镜回放已正确区分：昨夜坐姿 → 连续反打继承 → 次日清空 → 本镜明确站姿 → 空镜 → 回切继承站姿。模型回复及输入保存在 `.codex/posture-continuity-20260928/`。这验证读取与请求链路，不证明 H3 成片一定执行正确。

美漫第 12 章现有剧本的诊室前 17 镜，最终版本用真实本地模型 **2 次调用**完成读取，得到 **15 处有来源的姿态继承，0 项交接问题**；未写回历史剧本或生产目录。证据为 `clinic-final-calls.json`、`clinic-final-states.json`。初版曾把继承当成本镜明写，也曾因为不涉及坐站的动作引用而误拦；最终协议先列本镜证据再分类，只在姿态确实变化时检查动作依据。

全量 **1638 项测试通过（28.09 秒）**，记录为 `full-suite-accepted.log`。其中冻结的既有规划请求/报告对照保持通过；新测试跨过真实的打包、H3 请求组装和修复写回函数，模型边界使用模拟回复。真实模型回放与自动测试分别记录，没有把模拟回复当作模型实测。

本轮没有请求图片或视频生成，没有改历史成片及生产暂停状态。
