# 身份归一迁移评审与建议(2026-10-09,v2)

对 identity-auto-closure 设计(当前流程 vs 目标流程两张图)的评审。
结论:**方向正确,可以走。** v2 重写了一条核心哲学:身份归并里不存在"更高级的判断"。

## 〇、核心原则:没有谁的判断更高级

用户、agent、判官模型,在身份归并这件事上都是"读同样的证据做判断":证据清楚时谁判都一样,
证据不清楚时谁判都是猜。所以目标流程里**不要设计"转人工"作为判断升级**。改成三档:

1. **证据确凿**(原文直陈"我就是 XX"、自报家门等)→ 自动并;
2. **证据不足或叙事诡计**(变身/乔装/投影/亲属/同名)→ **不并,挂起**。
   "判不了"是合法终态:误并会毒化下游绑定(许流年案,15 章),不并最多多张卡、
   绑定差一点,章节照产。挂起不阻塞任何东西。
3. **不并就生产不动**(绑定沿别名走到空处、章节卡死,地牛案)→ 需要的不是"判断",
   是**解除阻塞的最小可逆动作**:按独立实体继续生产,证据到位再并(合并本来可撤销)。

用户的角色收敛为产品层裁决:"这个瑕疵能不能接受""这条命值不值得花钱重拍"——
不是事实查证。

## 一、目标态里必须保住的既有防线

全是事故换来的,每条附判据:

1. **逐字证据纪律**。合并/采用必须带能在原文定位的引句(`entities/evidence.py` span 定位)。
   判据:任一条 same_as 都能点回原文句子。
2. **叙事诡计默认不并**(`entities/contracts.py` transformation 护栏,许流年案)。
   证据含"变成/乔装/假扮"而无"同一人"直陈 → 挂起(第〇.2 档),不自动并、不升级给任何人。
   判据:构造变身证据走新流程,结果是挂起且生产继续。
3. **裁决与模型产出分离存放、重读重放**(`corrections.json` + `_correction_for`)。
   目标态改存储时等价物必须在:重跑读书/解析不得冲掉已有裁决。
   判据:光明纪元现有 239 条裁决迁移后逐条仍生效。
4. **绑不上就卡章**(`story/source_identity.py` active_cast_names 快速失败)。
   "复用已确认事实 + 增量处理新信息"之后,未确认的新指称仍当场拦停,不带 UNKNOWN 进分镜。
   判据:构造全书未登记的新指称,规划在绑定阶段失败。

## 二、迁移顺序与窗口

1. **先试点 shiri**(300 章已收官、数据干净、许流年/地牛两起名案都在它身上)。
   验收:全 300 章新身份源重绑与现状 diff 为零(除已知修正);不触发任何付费重生成。
2. **光明纪元等 133 集恢复收尾后**再动。它在产,台账刚被复核过(6 条旧合并撤销、
   239 条裁决)——最好的输入,最差的实验场。
   验收:239 条裁决重放一致;6 对被撤销的合并保持分离;绑定缓存口径不变或一次性全量重绑
   且零资产重生成。
3. **新书直接按目标态接入**。

## 三、设计图里要补明确的三个点

1. **别名归口**。今天别名有三处:`bible_aliases.json`、`reading_cast.json` 的 aliases、
   `chapter_aliases`(0b9996a)。目标态下写入口只能一个(台账实体 forms + 章级别名),
   两个旧文件变成同一份台账数据的导出。注意 `identity/store.py` 缓存键含这些文件——
   产出方变化触发一次性全量重绑,写进迁移说明,别被当成回归。
2. **judge_unknown 的落点**。它现在把判决写进 `reading_cast.json`(declined/characters)——
   这是"名单还是独立文件"的最后残留,目标态应写台账、名单由导出产生。
3. **疑点补读的预算上限**。归并 Agent 处理后续疑点是对的,但要有闸:每章疑点数、
   每疑点补读章数设上限,复用 `asked.json` 的"同一问题只问一次"做幂等,
   防止一个写岔的名字引发全书重读。

## 四、性能红线

settle 索引(实体→章节列表 + 内存 mentions)已落地,任何"核对采用"路径不得退回
逐对全扫。判据:光明纪元(799 章)全量身份复核 < 10 分钟。

## 五、不建议做的

- 不在光明纪元在产期间切换身份源;
- 不重写绑定算法(连通分量、UNKNOWN 卡章)——被事故验证最多的部分;
- 不引入新存储引擎/图库——JSON 事件文件 + 派生视图在这个规模(600 实体)是可审计优势。

## 六、最小验收清单(试点收工判据)

1. shiri 300 章重绑 diff 为零(或逐条可解释);
2. 四条防线判据测试全绿;
3. 端到端演示:构造一个"ch221 门外的人"式章内指称,走 疑点→补读→核对→采用/挂起→重绑
   全程无人工干预;
4. 构造一条变身证据:结果为挂起且生产继续(第〇.2 档);
5. 性能红线达标;全量测试绿,夹具口径同步。
