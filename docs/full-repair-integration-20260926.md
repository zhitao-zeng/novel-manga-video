# 完整 repair 接入及美漫十二上验收

2026-09-26。沿用 `codex/final-request-semantic-review`，承接上一轮七项修复与作者分镜权威调整。没有推送、没有合并或重启主产线；原始 B 版及失败素材保留。

## 原因与接通位置

上一轮单集入口只执行“翻译纠正备注＋换种子”，没有进入现有分镜修复。人工抽帧报告也没有进入 `episode_review.json`，所以完整 repair 的候选为零。

本次改为：确认问题绑定当前 take → 现有判因 → 身份问题查原文，分镜/请求问题改镜头，生成偏差重拍 → 编译与最终请求一致性检查 → 生成 → 按具体正向目标复审。反复出现的同一已确认问题自动升级为改镜头。未通过请求检查的候选不写回、不消耗视频次数。

- 修复及诊断显式接收分集目录，`12-1` 不再误读 `12`；Subject 对应来自共用引用定义，不解析过时英文模板。
- 已确认的问题不能被一次笼统的“fine”清掉；新视频须对具体问题复核。复核携带本次实际角色参考图，避免仅凭姓名猜身份。
- 复核先列观察与正向条件，再由程序汇总。视觉、声音、原文三个范围分开；静态帧无法听到台词，不等于画面失败。
- 上一轮已完成生成的次数一次性接入原修复历史；同一报告不重复计数，缓存不计新生成。修复中语音纠正更新待执行试次的请求绑定，避免漏记。
- 修改共享源阶段会重建必要的关联片段，保留对白范围和已确认参考图路径。
- 修复能同步写回 `sfx`，空字符串可清除旧动作音效；字段定义与规划共用。
- 面罩状态只补缺项。全程闭合时仅用闭合状态图；有开合过程才同时引用两种状态。闭合图的英文绑定不再要求从图中取不可见的脸和头发。

`render_clips_thin.py --review` 在渲染后接完整 repair；`--repair` 从已有成片开始。沿用现有执行器、历史、累计次数和候选发布，不增加队列。已有报告与当前计划/英文请求不符时，`--repair` 会拒绝用旧片报成功。

## 后续：19、20 复核修复（09-26 上午，Claude）
