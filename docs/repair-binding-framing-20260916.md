# 最终对白归属与镜头结构小试

已核验的说话者曾在后续重写或打包中回退，导致最终英文请求仍把台词交给错误角色。本次修复这条传递链，并对明确改变镜头结构的修法做了有限配对实验。归属保护已接入；结构修法没有测出额外收益，未扩大到生产路由。

## 工程修复

- `dialogue_binding.py` 只复用有当前原文引用、明确称谓归属且台词仍匹配的核验结果。过期、含混或与当前身份解读矛盾的记录不自动覆盖剧本；策略版本变更本身不再丢掉仍成立的明确姓名证据。
- 修段、原文复核与打包共用这些绑定。打包保存逐阶段的结构化对白；英文编译从该结构生成 Subject、画内/画外方式和台词，不再重新从自由文本猜说话人。
- 生成前校验最终英文请求的阶段、人物标签、台词及画内/画外方式；不匹配的请求不能占用生成槽。分段、合并和非语言音效仍遵守现有处理。
- SourceVerifier 按已有视频映射取证，按新提案理解意图。新请求与旧缓存不同不再导致“找不到原视频”；复核后仍检查视频身份未发生变化。
- 2188 章真实回归：原文核验文件写的是齐老，旧剧本和英文请求却写沈玄川。新打包和英文请求均保持齐老，验证输出见实验目录 `binding-proof.json`。正式产线以 `job-00543` 对 clip_09 做原文复核、旧片复用或后续恢复，未增加段级生成额度。

归属保护保证核验结果在后续处理中的一致性；最初核验结果仍需要原文证据和后续画面复审约束。

## 结构修法与实验约束

新增 `require_structure` 实验入口：改动必须体现在出镜人物集合或景别，单纯改措辞不算；已有的动作主体/对象不能被偷偷替换。旧稿未记录结构化动作时，以原文与两组共用的盲审约束结果。此入口默认关闭，生产现有路由保持。

冻结四个当前错段，A 为当前修段方法，B 为要求实际结构变化的方法。每对使用相同原文、对白、请求时长、seed、资产快照和 GPU052-A H3 实例；每臂最多一次提交，最多八次、78 秒请求时长，不生成新卡，不覆盖正式视频。语音沿用 observe 口径。

先复核冻结的原片，再对新片盲审，两组使用同一份原文和原场景意图。2382/clip_02 在复核时没有复现原先的动作对象错误，故排除，不计为修复成功，也没有生成 A/B。
