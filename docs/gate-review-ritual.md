# 规则复审纪律：gate 出生证明与误杀率复盘（2026-10-08）

产线的每条 gate（规划校验、安全门、内容检查）都是为了拦住一次真实发生过的
事故而存在的。事故会被遗忘，门不会自己消失；前提变化后，拦真事故的门会变成
误杀好章节的门。本文是新增、复盘和降级 gate 的固定纪律。

## 一、每条新 gate 必须有出生证明

新 gate 立项时在对应日期文档里写明三件事：防的是哪次事故（链接到带日期的
事故记录）、拦的是哪一层的错误（源文/剧本/打包/请求/素材/成片，见
production-lessons.md 的分层）、误杀的代价是什么。没有真实事故依据、只防
"理论上可能"的门不立项。现有门的出生证明：

- **姿态台账**：防美漫第 12 章姿态漂移。旧实验按场景号/地点把相邻镜头分组，
  "昨夜坐在诊室 → 次日仍在诊室"被错误延续坐姿，还用全镜动作关键词互相作证。
  见[连续性边界](posture-continuity-20260928.md)。
- **血迹门（FORBIDDEN_VISUAL 血液规则）**：防付费平台 SD 审核拒稿，写在第一本
  书的第一周，错误文案里带着当时的修法（"碑上的结果改写为无字的发光纹路"）。
  见 test_blood_gate.py 的历史记录与[十日终焉接入](shiri-sd25-pilot-20260929.md)。
- **身份绑定规则**：防剧本安错人事故——动作主体和对白被安给错误对象、丢了来访
  原因，剧本层错了，翻译和重拍都无法补救。见[共享身份规则](shared-story-identity-20260916.md)
  与[修复归属与构图](repair-binding-framing-20260916.md)。

## 二、每月按 gate-events.jsonl 复盘误杀率

`gate-events.jsonl`分别记录一次规划运行的开始（run）、门触发（firing）与
明确结局（outcome）。三者通过run_id关联，触发记录另带尝试序号和门code；
最终结局包含passed及仍导致失败的fatal_codes，不再次记成触发。
分集目录分别保留当前运行；较旧运行晚结束也不会覆盖新运行的结局。

月度复盘用 `gate_stats.gate_report` 的口径，按门聚合三个数：

- `blocked`：该门触发总次数；
- `fatal`：最终判定包含该门的失败运行数；
- `passed_chapters`：触发过该门，且最新已记录分集规划均明确通过的章数。

中断或尚未完成的运行不算通过。旧日志没有run_id和明确结局时无法可靠归因，
不混入新口径，不根据“没记录fatal”猜测成功。规划通过仍不等于成片验收通过。

读法：**blocked 高、fatal 低、passed_chapters 高 = 该门经常响、但响过的章节
最后过了 = 值得复核**，进入第三节的证据检查。这些是触发/结局计数，不是
误杀率；fatal高也不能单独证明拦对了。修改后通过可能说明真正的问题被修好，
不能据此给门降级。降级判断必须配合被拦镜头、原文和实际结果。

跑法（主仓 venv，对某一本书）：

```bash
PYTHONPATH=$PWD/src /mnt/disk1/zengzhitao/novel-manga-video/.venv/bin/python -c \
  "import json, sys; from novel_manga.planning.gate_stats import gate_report; \
   print(json.dumps(gate_report(sys.argv[1]), ensure_ascii=False, indent=2))" <书目录>
```

每月一次，结论（哪些门疑似过度拦截、处置决定）写进当月日期文档；决定不动
的也要留一句理由，避免下月重复评估。

## 三、误杀率高的门降级 report-only 的流程

以血迹门 2026-09-29 拆档为先例，四步：

1. **先实测被防对象的当前行为，不凭记忆。** 血迹门的前提是"平台会拒血"；
   SD2.5 实测带血迹的卡照常过，前提已经变了（见
   [十日终焉接入](shiri-sd25-pilot-20260929.md)）。前提没变就没资格降级。
2. **能拆档就拆档，不整门删除。** 按严重度把门分两档：误杀档降为
   report-only（进 warnings，带 "report only:" 前缀），真会出事的档保留硬拦。
   血迹门拆为血迹级（血迹/血泊/血手印）report-only、伤口级（渗血/流血/伤口/
   断肢）硬拦；对不审核的本地 H3 两档都静默——不拒血的服务不需要血迹警告。
3. **降级不是删除。** 事件照记 `gate-events.jsonl`，下月复盘时专门看
   report-only 之后是否有真事故漏过；漏过就升回硬拦。
4. **把历史和理由写进测试。** test_blood_gate.py 的 docstring 记录了"为什么
   这门是这个形状"，下一次复审才能读到，而不是再交一次学费。

血迹门的另一条独立教训一并记入纪律：**作者定稿分镜任何情况下都不送重写，
只报告**——该门曾把美漫心灵导师九章的镜头送进补丁轮，ch1 shot 12 狗斗被改
写成意识宫殿走廊、镜号丢失。降级评估时先确认门没有触碰作者定稿。

## 四、复杂度预算：新增机制先答"它和哪个现有东西合并或替换"

任何新机制（门、台账、检查、修复路径）立项时先回答一个问题：**它和哪个现有
东西合并，或者替换掉哪个现有东西？** 答不上来就不加。判别口径：

- 能挂进现有循环的不开新循环。姿态台账接在现有 `patch_plan` 循环、打包读取
  和修复写回里，没有新增队列、进程或视频生成入口
  （见[连续性边界](posture-continuity-20260928.md)）。
- 同层职责不并立两套。人物身份台账、穿戴关系、面罩状态表、姿态台账各管一
  摊；新状态先进既有表，不新开一本账。
- 每月复盘时同步检查：新规则是否已让某条旧规则变成重复或前提失效；是则
  降级或删除旧规则，不新旧叠加。
