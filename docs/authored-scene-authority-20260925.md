# 保留模型拍摄决定，收缩程序的语义改写

基线：96dce18。修改在 codex/final-request-semantic-review 工作树。用户要求先判断程序是否必要，再修复；不新增最终请求 LLM 审查阶段，不重拍视频。

## 本轮改变

- `in_frame` 统一为真正可见的人，包含可见听者；明确的空名单不再被 clip 角色表填满。普通规划也保存该名单。
- 动作主体和目标可以在画外。程序不再据此补人或否决在场模型的判断。
- 保留完整事件，不用字符串相似度判断“漏了动作”并追加 actor/action/target；规划、修段和说话人分组都使用作者的事件。
- 构图补充仅传递明确的可见名单，不安排左右、前后、正脸、背影或禁止谁动作。听者身份与镜头朝向分开。
- 后续阶段只使用该阶段的起点，不再同时塞入上一阶段末态。说话人分组后的回复承接作者写出的结束状态，不另写反应动作。
- camera/light 每镜独立填写，新稿不再允许仅写“同上”，已有规划补丁会处理这类字段问题。旧稿和人写分镜里的“同上”按旧提示词的原意执行：沿用阅读顺序上一个明确值、换场重来，不用装甲/反光关键词删改光线（见文末复核修正 1）。
- 瞬时光效和声音由事件说明出现与停止，不当成后续镜头的常驻环境光。穿戴资产名不追加“面罩打开”等后缀；外观状态写在已有起止画面字段中，避免破坏资产索引。
- 原有在场 LLM 复核移入规划校验/补丁循环，并带上原文。名单与画面矛盾成为局部规划问题，返回模型修改；不再在最终落盘前悄悄改名单。正常稿仍使用原有在场调用，发现问题时可能增加有上限的补丁/复核轮次；补丁用完分歧仍在时，保留编剧的名单并写入报告，不整稿重写、也不让本章失败（见文末复核修正 2）。
- ~~超长单镜也进入现有补丁循环~~（实跑失败，已改回由打包器在台词之间切，见文末复核修正 4）。补丁仍可返回第一镜及 continuations，只用于切不开的超长镜（作者定的时长、过长的无声动作）。替换和插入都按原始索引执行，展开前镜不会错改后镜。补丁结果另存为既有原稿 JSON 形式的证据文件。
- 打包遇到超过供应商时长上限的镜头，在台词之间切成几段，不改台词、不补写动作；只有切不开的才报告需要明确拆镜（见文末复核修正 4）。旧“自动创造新分段”工具（resplit）仍拒绝运行。已记录的历史分段对白范围恢复保留，旧视频、缓存和历史不迁移、不重置。
- 精判没有检查的地点、昼夜、聊天文字、画面缺陷、完整剧情不再填成通过。错误类型只按实际证据填写；多身体/换脸等不再全部归成动作归属错误。必修、原文特殊设定复核及同一素材证据优先级保留。

## 保留的程序职责

字段、编号、引用、已确认别名、说话人/声线绑定、供应商时长限制、字幕与合成、缓存、锁、生成次数、修复历史和发布规则。旧报告不批量回写；新的真实审查使用新的证据口径。

## 外部核对的两处事实修正

本次 11:28 跑数实际使用的 `series_assets/props/prop_001/turnaround.jpeg` 是无脸、闭合面罩空甲图，不能沿用更早一版带脸卡的诊断。

H3 的 Subject 不等于演员数。[官方参考指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md) 明确包含人物、环境、服装、道具等。因此人物和装甲分别有标签不能单独证明输入要求两个身体。合成穿甲卡是否改善生成，仍需要独立对照。

## 尚未验证与未纳入

这轮没有调用真实图片/视频生成，也没有测量改动后的口型错误率。技术回归不证明 H3 遵循拍摄意图。

“先生成无声画面，再混入心声”会改变音频生成和后期策略，本轮没有接入；另一会话提到的实验需要定位完整证据再采用。面罩状态更明确也不等于已验证模型稳定执行。是否新增最终请求语义复核，应在移除这些重复改写后，再看现有复核还漏什么。

旧稿的长镜头由打包器在台词之间切，旧稿的“同上”照原意执行，都不要求重新规划。本轮没有把旧稿强行改成另一种画面。
