# 剧本、修复与编译解耦 · 2026-09-16

本轮保持模型请求、审查门槛、修复路由、片段预算、产物字段和缓存策略。不新增数据库、队列或剧本文件格式。

## 规则归属

| 所有者 | 职责 |
|---|---|
| story/fields.py | 规划与修复共用动作、临时角色、入镜人物和对白字段；保留完整分镜与补丁不同的必填字段。现有两种提示词表述集中存放，不改变请求文本。 |
| story/scene.py | 通过 SceneContext 解析人物、物件和已确认对白，返回 ResolvedScene；不读取文件或调用模型。 |
| scene_context_thin.py | 从既有文件读取本章证据，供共享解析使用。 |
| story/framing.py | 现有站位规则，与动作身份分开维护。 |
| story/compilation.py | 使用独立 CompilerOptions 切段、编译请求与恢复片段范围；不依赖执行脚本的全局状态。 |
| build_clip_plan_thin.py | 命令行与文件、参考资产准备适配；正式重建调用携带本次操作的编译配置。 |
| repair/policy.py | 现有原文复核、直接重拍、重新构图的决策优先级。 |
| repair/execution.py、repair/proposal.py | 内存中的场景修改和 RepairProposal，不写修复历史、不调度下一轮。 |
| repair_flow_thin.py | 读取材料、调用模型、验证候选、编译候选，交给写入层；不导入修复管理器。 |
| repair_publication_thin.py | 保留原历史、备份、剧本、计划和审查记录的写入顺序。 |
| managed_repair_thin.py | 调用决策、执行和写入服务，管理原有缓存与有效生成次数。 |
| repair_clips_thin.py | 原命令行入口，参数不变；Python 调用方使用流程或共享模块。 |

依赖方向为：操作与编排 → 处理与编译 → 共享规则。命令入口可以调用管理器，修段处理模块不再反向调用管理器。

## 内部接口

- SceneContext 提供本章人物、别名、类型和对白证据，不自动请求新判断。
- resolve_scene 不修改原始剧本，返回独立的 ResolvedScene。已经解析的结果可再次传入，返回独立副本，不再次套用别名链。
- ClipCompiler 保存一次操作的配置副本。正式调用传入录制计划的片长、画幅等参数；脚本入口保留原默认参数。
- RepairProposal 包含既有候选剧本、计划、备注、变更范围、失败说明与结构修复信息，转换回原有结果格式，不新增落盘格式。
- propose_episode 不发布候选剧本；repair_episode(..., apply=True) 由流程层调用写入服务。已核验说话人证据的原记录时机保持不变，与发布候选剧本分开处理。
