# 定稿分镜绑定与提示词精简（2026-09-29）

## 已发现的问题

美漫短版 clip_05 的作者分镜写了托尼离开、随后返回，但绑定提供了与动作不符的起止状态，且引用了原文中另一段对话。中文编译将两者同时送入翻译。不能把这些输入矛盾归为 H3 执行偏差，也不能据此证明多余机甲只有这一种成因。

调用链还有一项确定的职责冲突：`call_model` 对定稿分镜仍调用 `generate_outline`，再用通用编剧指令要求按照新提纲写镜头；绑定 Schema 和 merge 却保留作者原有镜头。旧绑定说明还要求返回实际已不在 Schema 中的 location、turns、sfx。

## 本轮修改

- 定稿分镜直接一次结构化绑定调用，不再重写提纲；普通原文规划仍沿用原流程。
- 绑定只从当前分镜提取动作与起止状态。原文供事实核对与引用定位，资产资料供身份确认。进出等状态变化不能被静态继承覆盖。
- 移除绑定请求中的创作预算、原文保留台词指令和旧重复说明；保留原文、定稿镜头、人物资料及引用长度等绑定约束。调用方输入不被修改。
- 不改 merge 的字段交接、时长、台词、音效、缓存或生成预算。
- H3 翻译指令合并重复约束，保留进出、可见性、穿戴与独立物件、数量、参考标签和声音规则。保留最终六段请求格式、声线与对白绑定、书级画风。没有证据支持删除画风即可稳定消除多甲/金色面甲。

字符数（不是 token 或完整请求大小）：通用编剧基础指令 4,434 → 专用绑定 517；H3 翻译指令 2,650 → 1,279。已有分镜路径省去一次提纲模型调用，实际速度和视频收益尚未测量。

## 验证边界

新增模拟模型回归：已有分镜只发一次请求、不调用提纲、不传重编预算，保留原文及离开/返回分镜；正确绑定返回经过真实 merge 后，起止状态与作者动作不被改写。这个测试不证明模型一定能返回正确状态。

已有冻结回放的 51 个其他顶层结果不变，仅 translation_contract.shots 因本次精简更新；包括已有请求、绑定、缓存和路由对照。未调用图片、文本或视频生成服务，未修改历史成片或清空预算。

## 后续优化的顺序

1. 在正常 pipeline 重跑时观察专用绑定是否仍产生起止状态冲突；不要先用视频重拍验证错误的文字输入。
2. 若仍有明确矛盾，复用现有规划审查/补丁入口定位当前镜头；不在编译阶段靠字符串生成另一套动作，也不新增一套审查服务。
3. 仅对确需连续性的相邻镜头讨论实际成片末态接续；整集逐镜串行、每镜新增关键帧均不作为本轮默认方案。
