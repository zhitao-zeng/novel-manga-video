## 生成前准入

`scripts/clip_readiness.py` 检查当前请求的时长预算、源分镜编号、明确的切分遗漏/重复/不一致和必要图片路径。正常缺图先由原建卡流程补；补完仍缺失才等待。

- 旧切分能恢复的仍先走 `repair_split_ranges`，保持片段 ID 和正常片段不变。
- 已确认不可执行的片段不翻译新 H3 请求、不提交视频、不进入片段重拍循环。同集其他准备完成的片段照常生成并缓存。
- 全集没有可执行片段时不消耗整集生成运行次数；部分可生成时只执行准备好的部分，遇到阻挡后不会立即重复跑整集。
- 旧时长估算过高，但已有**请求、参考图、时长均匹配且通过语音门的缓存**时可以复用，不发新的超预算请求。不同请求或过期 H3 指令的缓存不能豁免。
- 原成片保留，缺片不拼接、不假报合格。检查结果在每集 `render_readiness.json`；调度状态显示 `plan_blocked` / `waiting_plan`。
- 总控 `state.json` 的 `plan_queue` 按章和片段列出原因；生成准备报告另标明 `repair_plan` 或 `restore_asset`。修复相关计划/源分镜，或所缺图片到位后，旧阻挡失效，总控回到原生成步骤。
- 这是阻止无效生成并形成待修任务，**不等于已自动解决所有旧切分异常**。不擅自整集重规划，也不降低画面精判标准。

只检查确定性请求约束，没有新增一轮模型判官。估时不等于对既有成片质量的判定；已匹配且通过的时长例外缓存由渲染器实际核对。

## 单集推进

`manage_repair_thin.py` 的新工作单元为一集，每集独立经历检查、修段、生成、复审和有界重拍。完成一集的当前步骤即可推进，不再等同批其他集。

| 约束 | 上限 |
|---|---:|
| 可执行修复在途章节 | 24 集 |
| 补渲生成阶段章节 | 12 集 |
| 补渲生成＋复审总占用 | 24 集 |
| 修复模型阶段工人 | 12 |
| 补渲复审工人 | 12 |
| 补漏确认、补审工人 | 各 6 |
| H3 共用请求并发配置 | 24（实际还受资源池槽位限制） |

每个新单集模型子任务只用一个工人。已有大批次按原子进程继续，结束当前步骤后才拆成单集后继；保留原轮次和章节归属。存量大批次可能暂时占用比新上限更多的待办章节，此时不继续补入新章节。

等待修计划的章节保留归属，但不占执行工人，不把其等待记为模型故障或已完成修复轮次；也不阻止其他可执行章节进入第二遍。全部只剩等待输入时总控保持 `waiting_plan`，有输入变化可继续。

`run_repair_step.py` 记录真实子进程退出结果，供总控重启后读取。正常退出还须核实视频确实完成；不能因批处理命令返回 0 就直接进复审。旧批次后继若对应成片仍旧或缺失，先回到生成步骤。
