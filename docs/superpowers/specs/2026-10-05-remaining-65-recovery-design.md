## 推荐做法

在已有 `input → apply → render → review → finish` 链路补齐能力，继续使用原生 Conductor 和 EpisodeTools。

单纯重开任务不会解决接口拒绝；整章重做会浪费通过片段。推荐按证据修正输入，只让受影响片段重新进入生成和验收。

### 1. 先回收已有成果

把当前选中视频、请求、输入修复回执、审核和最终 manifest 对齐。

- 缺审核或审核过期：复核当前视频，不重新生成视频。
- 已有合格片段、仅合成或交付中断：接着完成合成和技术检查。
- 审核疑似误报：只针对争议片段进行有界独立复核；不能把画面通过当成语音也通过。
- 黑屏/长静音先定位到原始片段或合成边界。合成造成的问题修合成；原始片段缺陷才进入输入修复和补拍。

### 2. 让 Agent 能修已采纳镜头的错误角色绑定

扩展现有 `action=input`，允许在明确的 `clip_ids` 范围内：

- 修正镜头的具名入镜人物、群演、听者及由此派生的角色引用。
- 根据原文申请缺失的实际人物素材，复用已有合格素材；缺卡的实际说话人不能触发默认替换成其他主角。
- 区分单人角色与群体。三名师团长、十八名圣徒等不能直接当作一个单人换装阶段，也不能用两个无关主角的卡代替。
- 修正服装、场景和错误的发声暗示。只有原文支持且独立核源通过的归属修正才允许改变说话人绑定；正确对白文本、镜头切分与时长继续保留。

路径为：Agent 提出有原文定位的改动 → DS 核源 → 复用/生成并审核实际素材 → 局部重编译 → Qwen 英文成稿 → DS 最终请求与实际参考图检查 → 发布修正 → 补拍。

候选阶段失败，不覆盖原有可用计划和视频。完成的素材和翻译可在同一候选中续用。仅依赖关系确实受影响的片段进入修复；不能把全章人物换装扩散到其他好片段。

第 397 章是验收案例：错误的林齐/玄蓝引用可以被核源后的正确人物/群演表达替换；缺失说话人被明确报告并处理，不再出现无法操作的 KeyError 或“只能修改旧选中角色”的循环。

### 3. 把无进展变成可执行的下一步

保留连续两轮无有效进展的停止上限。改善它接收到的状态和恢复流程：

- 当前状态明确给出剩余视频、输入方案、输入续接和独立复核次数，以及可执行的操作。
- 已支持的修法应出现在恢复提示中；旧会话的“已经结束”不能覆盖当前剩余额度与新增能力。
- 停止必须区分：没有有效提交、工具缺能力、输入方案被拒、服务失败、额度耗尽、外部原文缺失。
- 已有受理任务先完成；待工具返回时释放 Agent 模型容量；服务等待不算 Agent 无进展。
- 宿主编程错误或接口不支持在产生素材/视频前返回明确原因，不作为已消耗的内容候选。既有真实拒绝和已用次数仍保留。
- 修过通用工具后，只让该修复覆盖且仍有可执行动作的章节获得本轮一次恢复；不靠反复清空停止标记循环尝试。

第 123、257 章用于验证：Agent 能看到当前可执行路径，不能连续复述旧的终止结论；如果确实无路径，须准确报告缺哪项能力/额度。

### 4. 语音、画面和技术问题分别处理

语音：区分专名识别误差、计划内笑声等非语言声音、漏对白、真正额外语音。结合原文、对白时间轴、原始 ASR 和现有语音复核；必要的争议复核只做一次。DS 的文字/图片判断不能冒充直接听过音频。

无对白镜头却要求 murmur/retort 等发声时，由 Agent 改正有矛盾的源镜头/声景要求，保留邻接镜头中的实际剧情对白，再检查后补拍。不能靠静音整段、改字幕或删除证据放行。

画面：对漏人物、错身份、错误动作、异常服装/身体等，先对照源镜头、参考图与实际视频。输入错先修输入；输入正确而生成错误，才改拍摄表达并补拍。

技术：保持漏对白、额外语音、音量、连续静音、黑屏的严格检查。累计静音占比仍只是提示。技术或审核报告过期时重跑相应检查，不因旧结论产生无意义的新视频。

### 5. 次数方案

已授权的 32 次机会优先使用，仍受各片段现有条件限制。

对确认需要补拍且次数已耗尽的片段，建议本轮各追加最多 1 次；这属于新增额度建议，本次只写方案，不发放。当前已列清单的追加上限是 59 次，复核后不需补拍的片段不追加。整集技术问题新定位出的片段先补进同一台账，仍按每段最多一次核定，不能默默视作包含在原 59 段中。

批准本轮额度后，先记录“待有效修复与预检激活”的资格，以便修输入能够进入执行；实际 H3 请求仍只能在有效修正及实际参考图预检通过后使用。重复启动同一轮不得再加一次，累计物理次数和之前授权记录完整保留。

每个输入候选最多一次实质修正；服务中断只续接已完成步骤，不反复绘制相同素材。新的技术故障单独记录。新增加的一次仍失败就保存具体证据，进入下一次明确决策，不自动继续烧额度。

### 6. 两个特殊任务

- 第 125 章：原书第一百二十六章《意外收获》。现有原文只有 213 字。检查用户已有授权文本与可合法访问的完整来源，取得正文后走同一流程；缺正文期间保留为明确外部阻塞，不能编造原著补齐。
- 第 76 章：旧候选保持隔离。对必要剧情设计非性化、非露骨的安全改编，先核源与内容审查，再重新进入生成；不通过改年龄来绕过原问题。无法安全保留的展示不生成。

## 执行顺序与验收

1. 先实现通用工具修复及回归测试；此次不逐章写修复稿。

3. 按类别验证放行，某类工具仍失败不阻塞已验证的其他类别。随后把剩余普通任务全部纳入原生 Conductor；两个特殊任务有独立恢复条件。

6. 每章结果必须是通过、仍在运行/等待具体依赖、或带证据与恢复条件的阻塞；`finished_with_issues` 不计为完成。新通过必须同时有最新内容审核、技术通过、有效成片和源镜头追踪。
