# 小说短剧方法论与生成策略

## 1. 范围与结论

本文来自对“秋沐泽”账号六个不重复竖屏短剧样片的逐镜、字幕和音频分析。样片由小云雀 / Seedance 系列生成；本仓库并不依赖小云雀，实际链路是本地规划、生图、TTS 与外部视频 API。因此，项目学习的是成片的导演方法和质量标准，不复制特定产品后台。

仅凭成片不能确定创作者实际提交了哪些素材或后台参数。下文把可从成片确认的规律与建议实现分开描述。

核心结论：

> 吸引力来自冲突、反应和信息揭示，不来自持续运镜，也不来自把小说完整念出来。

原链路容易形成“小说原文 → 摘要旁白 → 配图 → 让画面动起来”的动态有声书。目标链路应当是“原文事实 → 戏剧问题 → 信息重排 → 人物表演 → 镜头与声音设计”。

## 2. 样片的可观察规律

六个不重复样片总时长约 12 分 45 秒，1080×1920、30 fps。粗略场景变化统计显示：

- 全片平均约 2.05 秒出现一次镜头变化；
- 前 15 秒平均约 1.73 秒一次；
- 镜头变化主要用于说话人、反应、道具和关系揭示，而不是持续环绕或无动机推拉；
- 声音几乎保持连续，但连续的是对白、音乐、环境和反应音，不是从头到尾的解释性旁白。

高频故事结构：

1. 0–3 秒先给出最容易理解的异常结果；
2. 立刻建立人物关系或地位落差；
3. 用一个具体道具承载误会、秘密或身份；
4. 每 10–15 秒让观众对关系的理解发生一次变化；
5. 结尾回答当前小问题，同时打开更大的关系或身份问题。

参考样片里的手链、纹身、证件照等道具不是装饰，而是信息载体。玄幻、悬疑和复仇题材也需要各自的等价物，例如测试装置、戒指、证据、合同或身份凭证。

## 3. 通用改编层与题材发动机

方法论可以用于小说，但不能把甜宠误会模板直接套到所有题材。系统分为两层。

### 3.1 通用改编层

- 保留原文事实、人物关系、关键因果和当前章边界；
- 允许重排当前章信息的出现顺序；
- 每集只选择一个最强戏剧问题；
- 结果前置必须有当前章证据，不能借用后文章节答案；
- 如果冷开场预览后段事件，必须回到原因，并在正常因果位置再次兑现；
- 关键事件保留，支持事件可合并或压缩，纯纹理描写可以删除；
- 原文证据与改编镜头始终保留映射。

### 3.2 题材发动机

| 题材 | 戏剧发动机 | 建议旁白上限 |
|---|---|---:|
| 甜宠 / 言情 | 关系误判 → 细节露馅 → 情绪试探 → 暧昧反转 | 12% |
| 玄幻 / 仙侠 | 公开受压 → 身份反差 → 能力谜团 → 异象或反击 | 20% |
| 都市 / 复仇 | 不公平事件 → 主角隐忍 → 对手加码 → 公开反击 | 14% |
| 悬疑 / 推理 | 异常细节 → 错误解释 → 新证据 → 原判断被推翻 | 24% |
| 成长 | 能力缺口 → 失败代价 → 主动选择 → 微小进展 | 20% |

旁白比例按发声字数计算，不是按 turn 数量计算。它是上限而不是必须填满的配额。

## 4. 剧本导演契约

每集在分镜之前先建立 `EpisodeDramaturgy`：

```text
genre_engine            题材发动机
dramatic_question       本集唯一核心问题
cold_open               0–3 秒先看到什么
cold_open_source_quote  当前章逐字证据
status_before           主角开场处境
conflict_beats          3–5 个冲突节点
reveal_order            信息揭示顺序
status_after            结尾处境变化
cliffhanger             最后一问
narration_budget_ratio  题材旁白预算
```

### 4.0 改编契约：verbatim 与 derived

一章小说通常只有约两成文字带引号，其余七八成是叙述——而因果、动机、来历和转折几乎都藏在叙述里。如果台词只能逐字引用，叙述就只剩"压成旁白"或"删掉"两条路，而旁白又被 `narration_budget_ratio` 压着，结果是一集只剩摘录出来的零散对白，观众看不懂人物为什么这样。

因此每个 turn 必须声明 `derivation`：

| 值 | 语义 | `source_quote` 要求 |
|---|---|---|
| `verbatim` | 逐字引用原文引号内的台词 | 归一化后 `turn.text` 必须是 `source_quote` 的子串 |
| `derived` | 把叙述外化为角色真会说出口的话或可拍摄的反应 | 必须引用**含叙述**的原文，且不得引入原文没有的事实、人物或事件 |

配套硬约束：

- 原文带引号的台词一律归给具体角色，**绝不能标成旁白**。
- 旁白 turn 不得含第一/第二人称（我/你/您）——第三人称全知叙述不会说"我"，出现即说明这是一句丢了说话人的角色台词。
- 不得把原文引号内的台词改写成近似句：台词**要么逐字引用，要么由叙述外化**，没有第三种。
- 承载因果、来历或转折的叙述事件，在 `adaptation_ledger` 中使用 `externalized`，而不是 `compressed`。
- 长段来历、回忆或规则说明不要交给单个角色一口气独白，拆成有听者的一问一答，让悬念由角色问出来。

这四条由 `evaluate_script_quality` 阻断，分别对应 `narrator_speaks_character_line`、`verbatim_turn_not_quoted`、`derived_turn_paraphrases_dialogue`。

### 4.1 Showrunner 决策层

`EpisodeDramaturgy` 回答“这一集讲什么”，`ShowrunnerPlan` 进一步回答“观众为什么继续看、谁知道什么、人物发生了什么变化”。它必须先于镜头执行产生：

```text
RetentionPlan
  4–8 个相对时间节点：hook → question → escalation → payoff/reversal → cliffhanger
  每个节点绑定当前章事件、镜头、逐字证据、观众问题、承诺和情绪变化

InformationState
  一个事实的真假状态、观众认知、各角色认知或误解、信息差用途和揭示节点

CharacterStateDelta
  人物本集前后发生变化的社会地位、关系、力量、情绪、信心和服装状态
  永久脸型、发型、体型不属于剧情状态
```

留存节点使用 0–1 相对时间而不是写死第 5、15、30 秒，适配不同集长。默认最大注意力空窗为全片的 25%；冷开场落在前 5%，集尾悬念落在后 20%。每个刺激都必须引用当前章事实，不能为了密度制造原文没有的羞辱、身份或反转。

规划失败时，确定性后端会生成 `planning_mode=inferred_fallback` 的保守计划并留下 warning；正式规划模型应输出 `planning_mode=planner`。质量门禁会拒绝无证据信息、无实际变化的人物状态、过大的中段留存空窗，以及未绑定留存节点的镜头和音频节拍。

OpenAI-compatible 与命令规划后端使用独立五阶段流程：章节事实诊断 → Showrunner → 剧本 → 独立审稿 → 连续性状态提交。Showrunner 阶段尚无镜头编号，只规划事件级留存、信息和状态，`shot_indexes` 必须为空；剧本形成后，控制器根据 `event_ids` 确定性绑定镜头编号，避免让一个巨型 Prompt 同时决定商业节奏和所有摄影细节。

删除旁白时依次判断：

1. 能直接演出来：写进动作；
2. 人物能自然说出来：改成原文对白；
3. 能通过反应暗示：用近景、停顿或道具；
4. 只有无法视觉化的时间、空间、必要规则和内心转折保留旁白。

镜头不是句子容器。一个连续镜头承载一个清楚的戏剧 beat，可以包含 1–3 个自然语义 turn；字幕分页由音频对齐层完成，不能为了两行字幕增加切镜。

## 5. 人物设计方法

角色不能只保存“姓名、年龄、外貌、服装”。建议角色圣经固定：

```text
visual_archetype    社会与戏剧类型
face_anchors        3–5 个不可漂移的五官锚点
silhouette          远距离也可辨认的轮廓
hair                发型结构而不是简单颜色
palette             角色专属颜色
base_costume        基础服装
episode_costumes    有证据的换装
signature_prop      剧情识别道具
expression_profile  表情幅度和主要发力部位
motion_signature    惯用姿态、手势与动作节奏
voice_profile_id    稳定声音身份
```

不同角色要形成视觉和表演反差：主角、权力角色、喜剧角色、支持者不应共享同一种脸、配色、姿态和情绪幅度。

永久身份资产与逐集剧情状态分开保存。`CharacterEpisodeState` 记录当前位置、目标、伤势、社会地位、关系位置、力量、情绪、信心和服装；`CharacterStateDelta` 只记录当前集有原文证据的变化。只有剧本通过门禁后，变化才提交到下一集的 `SeriesState`。信息差也以带集号和原文证据的 `SeriesInformationState` 跨集保存，避免一次失败规划污染后续连续性。

## 6. 生图资产策略

生图模型负责“谁、哪里、固定什么”，不负责整段时间表演。

### 6.1 人物定妆资产

```text
东方玄幻少年角色定妆，约十六岁，清瘦但不羸弱，
黑色长发束起，深色窄袖练功服，眉眼曾经骄傲、现在克制疲惫。

锁定脸型、眼型、鼻型、发际线、发型结构、体型、服装剪裁和配色。
单人四分之三正面、从头到脚的选角定妆照，脸部足够清晰，
轮廓和主色一眼可辨。纯净背景，无剧情动作、无其他人物、无文字。
```

定妆资产不是剧情关键帧，不放当前镜头的动作、场景和道具。

### 6.2 表情与身份锚点

```text
保持图1完全相同的脸、年龄、发型和服装，生成四分之三正面单人胸像。
选择该角色最有辨识度但尚未到高潮的基础表情，主要通过眼神、眉形和嘴角表现。
眼睛、眉形和嘴部无遮挡，肩颈与领口完整；无九宫格、无分身、无文字。
```

### 6.3 空场景资产

```text
东方玄幻家族测试广场，青灰石板地面，中央为无字黑晶测试装置，
背景是台阶和家族建筑，冷色晨光，前景、中景、背景层次明确。
为一至两名人物站立、走动和视线交流预留空间，避开字幕安全区。
严格空场，无人物、人体剪影、照片人物、文字、数值和水印，9:16。
```

### 6.4 剧情锚点关键帧

只有站位、交互、结果或道具关系必须锁定时才生成：

```text
图1锁定主角身份，图2锁定测试广场，图3锁定测试装置。
竖屏中近景，主角站在装置左前方，手刚离开晶石，身体短暂僵住；
背景人群形成半包围，但不遮挡主角。晶石只有不可读的冷光纹路。
这是嘲笑发生前一瞬，为后续握拳和抬眼保留动作空间。
保持人物脸、发型、服装一致；无文字、数字、字幕、分栏和水印。
```

可读数值和剧情文字由后期叠加，不交给图像或视频模型绘制。

## 7. 自适应关键帧决策

默认策略为 `adaptive`，不是全有或全无。

| 镜头 | 视觉输入 |
|---|---|
| 单人普通对白、反应 | 人物资产 + 空场景 |
| 无人物空镜 | 空场景资产 |
| 普通走路、转头、握拳 | 人物资产 + 空场景 |
| 多人精确站位 | 剧情关键帧 |
| 递物、抓手、拥抱、打斗 | 剧情关键帧 |
| 关键道具交互 | 剧情关键帧 |
| 结果揭示、高潮反转 | 剧情关键帧 |
| 封面级构图、集尾特写 | 剧情关键帧 |

运行时必须记录 `visual_strategy` 和 `keyframe_reasons`。

上表读作"视频模型收到的参考输入"，不是"是否生成关键帧"。两条路径都始终生成关键帧作为首帧条件图：人物资产是灰底全身定妆图，直接送进视频模型只会得到站在空背景里的人，场景、景别和调度全部丢失，必须先由关键帧把人物与场景合成为真正的场面调度。

- 本地 MiniMax H3 支持在关键帧之外**追加**人物资产（Picture 1）与空场景（Picture 2）作为额外参考，由 `_direct_h3_assets` 决定；空镜可只追加场景资产。
- 当前 PhanRouter SD2.5 适配器只提交一张 `reference_image`，无法追加，所以 API 模式下 `visual_strategy` 只影响关键帧提示词的构图约束，不改变生成路径。这是适配器接口的限制，不是回退失败。

因此 `direct-assets` 的语义是"给视频模型追加身份锚点"，不是"省掉关键帧"。

## 8. Seedance / 视频提示词

视频提示词负责“时间里发生什么”，不再重复完整绘制人物。

```text
@图片1是主角的唯一身份参考，只参考脸、年龄、发型、体型和服装。
@图片2是测试广场空场景，只参考建筑、装置、光线和空间结构。
@音频1是锁定对白，必须完整保留台词、音色、语速、停顿和情绪。

生成9:16连续单镜头。

镜头戏剧意图：本镜承担公开结果揭示；权力关系是主角被群体压低；
观众焦点只放在测试结果和主角克制反应；绑定冷开场留存节点。

开场：主角先看向测试装置，嘴巴闭合。
触发：听见周围议论，视线下沉，右手缓慢握紧。
主要动作：按参考音频开口；下颌克制，前半压住情绪，最后才抬眼。
收束：说完立即闭嘴，保持坚定眼神一拍。

摄影机为胸部以上中近景，固定机位。不推拉、不环绕、不数字缩放。
只有在台词含义、视线目标、道具状态或对方反应触发时改变动作；
一个节拍只做一个主要动作，允许停顿，不用无意义小动作填满时间。

不得新增具名人物，不变脸、不换装，不出现文字、字幕、Logo或额外对白。
```

摄影机默认锁定。只有以下事件允许移动：

- 空间揭示：短横移或焦点转移；
- 人物明确位移：克制跟随；
- 权力或情绪转折：一次短促推近；
- 主观视点变化：有依据的主观运动。

每镜最多一条短轨迹，完成后停住；相邻镜头不得连续明显运镜。

## 9. 声音策略

TTS 只用于语言，不生成脚步、风声、笑声、音乐等非语言声音。

区分两类参考音频：

- 声音身份参考：每个角色一份 8–15 秒稳定音色样本；
- 台词表演参考：逐句锁定文字、语速、停顿和镜头时长。

建议生产分工：

| 声音 | 默认策略 |
|---|---|
| 关键对白、旁白、内心声、专有名词 | 逐句锁定 TTS |
| 次要感叹、群众低语、笑声 | 视频模型原生或独立声音模型 |
| 环境、拟音、转场声音 | 视频模型原生或素材库 |
| BGM | 独立音乐模型或已授权素材 |
| 角色音色 | 固定 `voice_profile_id` / voice anchor |

`SceneAudioPlan` 记录表演意图、语速、能量、停顿、音乐、环境、拟音和 ducking。当前生产交付仍以锁定 TTS 为准，因为现有 API 不保证分离人声、音乐和拟音；不能把模型完整音轨直接叠在 TTS 上，否则会产生双重人声。后续如 API 返回可验证的完整原生音轨或分轨，可增加“ASR 通过则整段保留，失败则整段回退”的模式。

每个镜头还记录相对 `AudioBeat`，例如：

```text
0%   ambience  建立广场低声议论
18%  impact    石碑结果真正可读时触发短促冲击
42%  duck      锁定台词开始时压低背景
90%  release   人物反应落定后留一拍
```

节拍由台词、动作、揭示或反应触发，而不是机械地每隔几秒放音效。目前这些节拍进入视频导演提示、生产计划、缓存身份和审计记录；仓库尚未提供素材库/音乐模型的可验证最终混音器，所以非语言声音是否进入交付音轨仍取决于媒体后端能力。

## 10. 《斗破苍穹》第一章示例

这里只展示结构，不复制原文全文。

```text
0–3秒    测试结果先出现，现场由安静转为嘲笑
3–15秒   主角反应与昔日身份形成极短反差
15–30秒  群体压力升级，不用旁白解释每个人
30–45秒  支持者得到高结果，却主动走向主角
45–65秒  主角独处，压抑情绪第一次外露
65–75秒  戒指或力量异常形成集尾问题
```

普通单人反应使用人物与场景资产直出；测试结果、两人关系站位和戒指悬念保留剧情关键帧。群众声、测试装置低频、握拳和山风不是 TTS；测试播报、主角内心声和关键对白保持逐句锁定。

## 11. 仓库实现

默认配置：

```bash
export NOVEL_CREATIVE_PROFILE=short-drama-adaptive-v1
export NOVEL_LOCAL_VISUAL_STRATEGY=adaptive
export NOVEL_INTRO_SECONDS=0
```

可回退到旧式忠实顺序和逐镜关键帧：

```bash
export NOVEL_CREATIVE_PROFILE=faithful-chronological-v1
export NOVEL_LOCAL_VISUAL_STRATEGY=keyframe
export NOVEL_INTRO_SECONDS=4
```

主要审计字段：

- `EpisodePlan.creative_profile`
- `EpisodePlan.dramaturgy`

## 12. 当前限制

- 无法仅凭成片确认参考账号实际输入了多少人物图、场景图、关键帧或音频；
- PhanRouter SD2.5 当前适配器不支持多张独立参考图，API 模式仍需关键帧回退；
- 当前最终混音仍使用锁定对白轨，模型原生拟音和音乐不会作为生产交付音轨；
- `AudioBeat` 已进入规划、提示和审计，但尚没有绑定授权素材库或声音模型的最终混音执行器；
- 本地 H3 的人物 + 场景直出是低成本路径，但多人物、道具交互和结果揭示仍需关键帧；
- 自动门禁能限制旁白、运镜和关键帧使用，却不能代替人工判断一个冲突是否真正有吸引力。
