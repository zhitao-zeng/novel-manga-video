**首遍完整性修复与 A/B 有效性复验 · 2026-09-14**

旧 A/B 的方案优劣结论已撤回。本轮修复了首遍产物与传递门控，并完成三章小样本复验。新结果确认流程完整执行；样本规模及内容审阅分歧不足以支持完整改编流程的整体排名。

**此前为什么不能下结论**

旧试验十二次首遍均返回 `finish_reason=length`，正式 `content` 为空。实现将未完成的 `reasoning` 末尾 3,000 字符作为提纲交给第二遍，同时宣称“内部规划已完成”。没有验证预定的 A/B 提纲实际形成，就把后续测量用于方法取舍，这是实验有效性错误。

两组都截断，不能证明两种完整方法得到了公平比较。旧日志和数字保留作问题证据，旧方案结论不再使用；此前独立测试的时长预算统一及一秒估时容差修复保留。[旧报告更正](/mnt/disk1/zengzhitao/novel-manga-video/docs/planner-outline-ab-20260914.md)

**代码修复**

1. 第一遍明确输出 JSON 提纲，使用 `enable_thinking=false`；A 填写片段安排、保留台词和预算三项，B 填写目标、因果、分场、表达、承接和预算六项，两组均列出所有原文区段的呈现位置。
2. 只有正常 `stop`、正式内容非空、必需项齐全、区段覆盖无遗漏或重复，才允许调用第二遍。解析通过不等同于内容质量正确。
3. 取消 `reasoning` 兜底及末尾字符截取。实际输出全文原样传入第二遍。
4. 默认首遍额度为 4,096 token，必要时有一次有界补试；本轮上限为 8,192。仍不完整则写入 `planning_failed.json`，标明 `stage=outline`，不调用第二遍，也不由外层循环重复整章请求。
5. 实验另外审计原始请求与响应，核对完整提纲和第二遍输入逐字相同；不能仅凭最终 `passed` 标签认定实验有效。完整性失败会停止后续样本，评审器拒绝对无效处理链给出 A/B 质量比较。

**实际模型复验**

两组均使用同一模型、种子、时长预算、完整性规则与冻结上下文，仅第一遍任务及所需提纲字段不同。两组共同改为显式 JSON 产物，因此新轮不与旧截断轮横向比较统计。

先检查输入条件，排除了所需地点未进入候选列表的诸天第 8 章，未对该章调用模型。本轮选择雾月第 2 章、星海第 4 章和第 2 章，核心发生地点均有可用候选。样本来自两本小说，不能代表全部题材和复杂场景。

|---|---:|---:|---|

六份首遍均在第一次请求正常结束，正式内容非空，字段及八个区段齐全。六条实际请求链均核验全文传递，无截取、无推理兜底；六份最终剧本均完成并通过当前结构检查。

这也说明问题不能简单归为“给模型的数字不够大”：旧流程把未完成推理当结果；修复后大部分明确提纲在约一千输出 token 内即可完成。高额度是容量上限，实际使用量按响应记录统计。

匿名审阅交换展示顺序后，雾月 2 为偏 B / 平局，星海 4 两次偏 A，星海 2 为偏 B / 偏 A。部分判断仍有分歧，不将这些票数当作总体质量真值。

人工核对到一个明确的后续问题：星海 4 的 B 提纲在因果、分场和承接三项中都写了“其他四头幼龙先成功飞上赤岚爪子”，最终 B 镜头却遗漏这一事件，A 保留了它。这次能定位到提纲完成之后、镜头编写时的遗漏；不能把它误说成首遍提纲没生成，也不能据单章就否定整个方法。

本轮不恢复旧实验的优劣结论。后续若评价完整改编流程，应继续核对提纲中的关键事件是否落实到镜头，并使用更多输入条件明确的样本。
