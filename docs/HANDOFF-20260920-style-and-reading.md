### 1.2 改了什么

`configs/styles/<name>.json`，五个键：

| 键 | 用途 |
|---|---|
| `visual_style` | 进 `bible.visual_style`，也进 `style_fingerprint` |
| `card_suffix` | 角色卡提示词尾巴。**留空表示让题材的 `card_style_suffix_3d` 生效** |
| `render_family` | `3d` / `2d` / `photo`，替掉三处字符串嗅探 |
| `render_direction` | 该画风自带的渲染措辞；`photo` 族在原有三个分支里没有对应文本，必须自带 |
| `prompt_fingerprint` | `false` 时指纹不进图像提示词 |

现有四个包：`3d-guoman`、`2d-cel`、`weimei`、`live`。
**丢一个 json 进目录就多一种画风，不用改代码**——所有 `--style` 入口都改成扫目录了。

**每本书建书时拿一份自己的副本 `outputs/<novel>/style.json`。** 改 `configs/styles/` 只影响之后新建的书，
不影响已经在跑的书（它的卡和指纹是用当时的文本做的）。三本在产书已各自冻结一份。

### 1.3 三个判断，别推翻前先读理由

1. **题材覆盖 > 画风包默认。** 五个 genre 的 `card_style_suffix_3d` 各不相同且是题材真活（fantasy 允许鳞片翼膜、
   gaslamp 要欧式面孔、xianxia 要古风布料体块）。它们都是**按 3D 国漫写的**，不是画风中立的。
   所以 `3d-guoman` 的 `card_suffix` 留空、让题材生效；画法不同的画风（weimei）写自己的、压过题材。
   我一开始定成"画风包统一覆盖题材"，看了五个文件内容后推翻了。
2. **指纹不该进图像提示词。** `style_fingerprint` 是 `sha256(书名+画风文本+所有角色外貌服装)[:16]`，
   两个用途：缓存/清单的键（合理），和直接拼进提示词（无意义——`保持…服装和 6cdfd91feee821c0 风格完全一致`
   对图像模型是噪声）。没有任何测试或文档说明后者为什么要有。**没有拆掉**：拆了会改三本书所有卡片提示词、
   触发重画。新包用 `prompt_fingerprint: false` 绕开，老书维持原样。
3. **weimei / live 的中文是草稿。** 沙箱原文是英文，中译正是 `HANDOFF-20260920.md` §2.3 踩过的雷。
   包里 `source_en` 存着用户认可过的英文原文（**不要改**），中文在 `review` 字段标了待确认。

## 3. 修掉的 bug

**建卡下载被代理掐断**（`870332c`）。所有 PhanRouter 调用都走 shell 代理，传几 MB 的卡图时代理中途断开
TLS，表现为 `ConnectError: UNEXPECTED_EOF_WHILE_READING`。真人版样卡 4.4 MiB 最大，连续失败四次。

`.env` 里 `NO_PROXY` 已经写了这个主机，但 **httpx 认小写 `no_proxy`，而 shell 只设了小写 `https_proxy`
和大写 `NO_PROXY`**——代理开着、豁免关着。给 client 加 `trust_env=False`（`local_h3`、`llm`、`planning`、
`moderation` 本来就都是这么写的）。复用同一批已付费任务直连重下 3/3 成功，与原图逐字节相同。

全仓最后一个没写 `trust_env=False` 的是 `bible.py:130`，没动（LLM 小报文，没暴露过问题）。

## 4. 陷阱

1. **`build_cards_thin.py` 传不存在的 asset id，照样报 `status: "built"`。** 我先传了 `character_000`
   （实际是 `character_001`，`enumerate(..., start=1)`），三次"成功"但一张图都没生成。
   **看产物，不看输出**——`find` 目录比读 stdout 可靠。这个 silent success 值得修。
2. **先确认失败发生在哪一步，再推断为什么。** 我看到"只有真人版稳定失败"就去设计内容对照实验，
   猜是审核。实际抓 httpx/httpcore DEBUG 日志一看，POST 一直 200、任务一直创建成功，断的是下载。
   这是 `HANDOFF-20260920.md` §4.10「不可能的读数先怀疑仪表」的延伸。
3. **我自己写的核对脚本也会坏。** 查证据时手写了个章节切分正则，结果 149 条全报"原文未找到"——
   正则没匹配上。改用 `score.py` 自己的 `quote_ok` 才拿到真实分布。**优先用项目已有的判定函数。**
4. **改了 `configs/styles/` 不会追溯已建的书。** 这是设计要的隔离，但也意味着样卡目录改画风后要重新
   写一遍它的 `style.json`，否则用的还是旧副本。我被这个绊过一次。
