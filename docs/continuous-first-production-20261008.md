# 持续首拍与独立验收

2026-10-08 审计发现：单段 H3 翻译失败会提前返回，整章无法进入生成；最终参考图检查还在生成 worker 内；整批 renderer 取一次快照后等所有章节结束；输入修复占满 Agent，171章正式验收数近4小时未变。标称待拍库存还包含被其他 worker 持有的任务。基线见运行批次的 `pipeline-audit-20261008/010353.json`。

本次改动：

- 标准准备逐段完成素材、当前英文、最终语音重排后的实际请求与图片检查。失败保留逐段原因，其余片段进入可执行库存。已有首拍不进入此路径。
- 实测补充：整章检查完才发布仍会耗尽库存。因此第一段通过就发布并释放章锁；这段生成后，未检查片段回到普通准备。优先已有图片和当前英文的片段，已失败且输入未变的片段不因这一轮次切换而重试。
- 生成入口只接收已放行片段，复用最终请求检查缓存；请求或图片变化导致缓存失效时交回准备，不在提交前临时占用文字模型。审核、切分、语音和物理拍摄预算保留。
- 每章一个 renderer worker，任一 worker 完成即可补入新章；旧整批 worker 排空后接管。源章 lease、重启后的存量 worker 和共用 H3 槽位继续防止重复生成。
- 有成片待审时预留2个审核宿主，输入异常最多占10个文字宿主；审核后台工具运行期间不无限新开审核。无审核积压时可借用空位。实际模型仍受 DS8/Qwen4 约束，H3仍优先首拍。
- 可用片段、处理中片段、阻塞片段与正式验收分别统计。已首拍完成的任务解除陈旧的等图标签，不充值时间或拍摄次数。共享素材显示 existing/prepared/needs_review/failed，处理结束不等于全部通过。

公共错误修复：角色参考声明使用 subject，不把动物默认写成人；旧 person 格式仍能读取，只对未拍请求规范化。姿态台账保留未改前缀的判断，后续原文和镜头输入未变时复用分类并重新计算继承状态。有证据的姿态依赖由编译器标明并在一次输入修复中处理，保留镜头切分、时长、对白、首次生成边界和拍摄预算；显式限定的资产状态不得借此扩展。共享异常素材由现有批次补做一轮实际图复核，只对确认问题沿用原有的一次重绘限制，重启不补充次数。
