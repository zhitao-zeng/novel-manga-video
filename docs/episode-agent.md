# 独立 Agent 产线

本分支增加按集运行的 Claude Code 沙箱入口。正式批量控制器与看板保留原有操作方式；Agent 入口由操作者显式启动。

每集使用独立工作区与持续会话。Agent 调用 `check`、`render`、`status`、`review`、`apply`、`finish`，自行安排创作与修复。主机执行现有视频供应商、缓存、ASR、合成和独立审查，保留实际生成次数与停止条件。

宿主在每次创作或续接时直接提供当前状态和上一次操作结果。`render` 自身先校验草稿，再执行允许的生成，调用现有独立审查并汇总验收结果，随后导出当前视频抽帧和原始 ASR 证据；相同输入与当前片段的已有审查由原缓存复用。Agent 无需另起一轮只为请求这些证据。`check` 用于草稿诊断，`review` 用于缺失或过期的审查。交接未结束时查询状态或再次提交操作，会明确返回需要结束本轮，不让 Agent 等待一个必须等它退出才会开始的操作。

待修阶段先审核原始片段，再决定是否合成整集。`render` 返回 `clips_ready` 和
`assembly_pending=true` 表示片段及审核证据已就绪，正在等待修复决定；没有整集文件
本身不要求重新拍摄。内容检查通过后宿主自动合成并执行原有技术质检。若决定带着
未解决问题收尾，`finish` 只用现有片段合成一次候选，并如实保留未通过状态。
`content_passed` 与最终 `quality_passed` 分开；后者仍要求技术和内容验收均通过。
报告记录审核、合成及技术质检耗时，供正常生产吞吐分析使用。

这些修改收敛工具往返，不扩大自动重拍次数。`source` 正常生产先由配置的模型直接提出草稿，宿主编译固定 H3 格式并执行；未解决的创作、素材或验收问题由 Agent 接管。`script` 路径适用于需要保持作者定稿的制作，继续冻结原有对白、镜头分组和时长。

正常路径的全量检查继续使用固定的结构、参考、ASR、视觉和技术检查调用，不需要每段
启动 Agent 对话。Agent 接手具体异常和有争议的判词，读取完整原文、当前分镜、实际
素材、视频证据和历史结果，选择修正文稿/参考/请求、核对误判或停止；修复成功后由
宿主继续调度。能自动完成并验收的集数可以保持零 Agent 调用。

审核保留片段引用的原文全文；旧中文事件句为空时，使用现有动作及穿戴绑定说明本镜。
同一个原文段覆盖多个镜头时，只核对当前事件阶段，邻镜的后续异象不能为当前错误
提供豁免。审查版本变化使旧判词失效，不会增加拍摄额度。

批量资源调度、同会话工具交接与暂停恢复见[Agent 集级制作与共享调度](episode-agent-scheduling.md)。

## 接入已有产物

```bash
python scripts/episode_agent.py prepare \
  --novel-dir outputs/你的小说 --episode 36 --input-mode script

python scripts/episode_agent.py run \
  --novel-dir outputs/你的小说 --episode 36 --input-mode script
```

`prepare` 只准备输入，不调用模型或生成服务。`script` 模式读取现有 `chapter_script.json`、人物库、读书记录、资产与片段计划，由 Agent 编写最终 H3 请求；现有对白、归属、分组、引用顺序和时长继续作为输入约束。缺少片段计划时使用原有打包能力确定性生成，所需资料缺失则报告原因。

已有英文会预填到 `output/requests.json`，输入清单列出可以复用的片段，以及确实缺失或违反绑定的片段。再次准备保留 Agent 已有编辑。正向描述继续作为写作建议；仅出现 `no`、`without` 等词不再使整份请求失效，诊断以 `style_warnings` 返回。对白、说话人、图片映射、切点和对白外中文仍是硬检查，实际参考一致性与成片验收继续执行。Agent 集中编辑具体缺项和问题，不必为统一措辞重写整集或自建校验脚本。

执行新 `script` 会话前，缺失的英文调用原有成稿器生成草稿，每段一次、每集至多两路，并共享已配置的 DS 容量。只填草稿中的空项，原计划、媒体和 Agent 已有编辑保留；成稿器报告的来源或素材冲突原样交给 Agent。单纯 `prepare` 仍只复制与检查输入，不调用模型。

新 `script` 任务的草稿若已通过结构检查，宿主直接调用现有 `render`，继续经过真实参考检查、生成和独立验收。全部验收通过时由宿主执行 `finish`，记录为已有请求的宿主执行；有错误、阻塞或待修内容时才启动 Agent，并提供同一批产物和剩余预算。`source` 创作和已经启动的 Agent 会话继续保留。整集吞吐应以实际运行计时为准，不用省掉的工具调用数代替真实提速。

H3 单次请求最多15秒。保存的计划若含超过该限制的片段，需要先按 H3 重新打包，入口会明确报错，保留原计划。

历史小说目录、剧本、素材与视频保留。准备过程写入独立的 Agent 输出目录，复制已有文件并复用该输出树内的资产快照；不会向原资产目录写入修复。

## 从原文创作

```bash
python scripts/episode_agent.py run \
  --novel-dir outputs/你的小说 --episode 36 --input-mode source
```

`source` 模式提供完整原文、读书证据和实际资产。已有 `lean/extract/ch-NNN.json` 的章节提取结果会复制到输入包，正常模型与 Agent 均可复用其中的人物、在场和外貌变化证据，不再为获取这些记录重新调用模型；原文仍是事实依据。

正常模型按宿主预分配的片段写 `clips/shots/beats`：人物、入镜名单、动作、机位、选材和台词由模型决定。程序从同一份按顺序排列的表演/发言生成镜头编号、对白列表、可见/画外发言和 H3 占位符，单镜片段直接使用分配的时长；多镜片段保留作者分配的镜长。普通稿不能少交或多交分配的片段。无词哼唱写在英文表演/声音描述里，不放进对白。此内部出稿形式转换成既有 episode 契约，已有分镜与 Agent 输出格式保持不变。

若 H3 画面/声音字段仍含中文，宿主进行一次专用翻译，已经合格的英文字段直接保留。翻译不能修改分镜、台词、引用或绑定标记；单字段失败不会丢弃其他合格译文。它与首次出稿共享操作时限，最多使用剩余预算中的 120 秒，不触发整集重写。原始模型稿和翻译结果各自保存，失败候选交 Agent 继续。严格检查采用后才生成、独立验收；正常通过时不启动 Agent。

初稿失败或验收有疑点时，同一工作区交给 Agent，保留对未采用草稿的创作修复权限，以及现有素材修复工具。已有文件或持续会话不重写；`source-draft-call.json` 保留一次正常调用的结果，模型错误不触发重复初稿调用。Agent 使用修复时间片处理已存在的模型草稿，缺稿时保留完整创作时间片。实际选择的参考图片仍需要检查；候选目录不再自动纳入废稿和备份图。

`prepare` 保持只准备输入。`auto` 为默认模式：已有剧本时选择 `script`，否则选择 `source`。操作时限用尽后不会启动新的拍摄，已经接收的任务继续收尾；完成结果按实际验收记录。

## 按批准备与运行

```bash
python scripts/episode_agent.py prepare \
  --novel-dir outputs/你的小说 --chapters 1-20 --input-mode auto

python scripts/episode_agent.py run \
  --novel-dir outputs/你的小说 --chapters 1-20 --input-mode auto

python scripts/episode_agent.py status \
  --novel-dir outputs/你的小说 --chapters 1-20
```

入口按已有章节编号逐集操作，不创建另一套任务队列。每集会话、预算和缓存独立保存；重复运行续用已完成的素材与历史。

失败结果默认保留。流程修正后可显式使用 `run --retry-issues` 重新处理已停止的集：保存旧会话与结果，以新作者会话和同样长度的执行时限继续，复用媒体、原始识别和实际生成次数。已验收通过的集不重跑，视频重试次数上限不增加。

批量控制器需要补接被提前收尾的作者时，可在显式 retry 中配置
`resume_session_on_retry: true`，保留原会话并归档其状态副本。它不自动重开任务，
也不重置视频、输入或复查额度；控制器应只给未用完的调用次数及执行时间。

## 配置与独立工作树

剧集 Agent 的通用默认预算为：整章操作90分钟，修复会话单轮10分钟，首次
原文创作单轮20分钟。当前任务配置与项目配置使用同一组默认值；已有更长的
显式设置保留。任务完成、连续无实质进展或拍摄额度耗尽时仍按实际状态结束，
不会因为时间上限较长而续加拍摄次数。配置预算的提高对新启动的修复窗口生效；
已运行进程继续安全收尾，原会话可由原生调度器续接。

已采用的分镜即使另开修复会话，也直接进入当前证据的修复流程，不再从头创作。
Agent 可先用 `check --file output/repair.json` 快速核对修复字段；这一操作不生成
图片、不消耗输入修复次数，实际来源与参考检查仍在 apply/render 中执行。

用户明确批准额外一次时，可在宿主 `repair_budget_grants.json` 的具体片段中保存
`conditional_extra`：授权标识、原因、固定的总拍摄上限和准备/复核上限。
待放行额度允许 Agent 准备修复；通过 apply 的具体修复后标记 prepared，再由
render 的实际请求和参考图预检通过后激活。单独接受风险不能激活；重启不补发。
其他片段的原上限保留，现有成片优先复用。
`remaining_takes` 展示全部已授权且未使用的次数，包括待预检的额外一次；
`conditional_extra_takes` 继续说明准备与激活状态。状态读取不会激活额度。
输入操作选错目标时返回可选的失败片段，保留同批其他合法修复。

`finish_existing: true` 仅运行宿主现有验收，用于书级 QC 口径变化。
被豁免的检查保存 `measured_passed` 和原始测量；移除豁免时恢复真实判定。
仅旧报告缺少被豁免的原判定时才重新测量。此入口不启动 Agent 或拍摄。

模型、凭据变量名、沙箱镜像来自现有 `configs/agent_sandbox.json`；视频资源使用已有运行配置。小说的画幅、风格、语音口径和质检配置保留。凭据通过环境或项目现有配置加载，输入包和日志不包含密钥。

可在任务沙箱配置分别指定 `h3_translation_endpoint` 和
`h3_request_check_endpoint`，值使用现有 `flashnext`、`deepseek` 等端点名。
前者仅选择英文成稿模型，后者选择请求与实际参考图的检查模型；未指定时沿用
原有环境模型。Agent、原文修复判断和最终审片的模型独立保留。
`h3_preparation_parallel` 默认2，把不同于Agent的辅助端点加入既有共享模型
槽池，所有章节共同遵守此上限；不会把主DS端点的容量改成2。
对应命令级变量为 `NOVEL_H3_TRANSLATION_ENDPOINT` 和
`NOVEL_H3_REQUEST_CHECK_ENDPOINT`。成稿诊断日志记录实际调用的模型名。

批量任务可在 `agent.config` 指定自己的沙箱配置路径（相对运行项目或绝对路径），
调度器与子进程使用同一份配置；单次命令对应 `run --config PATH`。
DS 的 `deepseek` 审核端点已由产品代码注册，不再依赖私有 worker 临时注册。
运行项目与代码 checkout 分开时，子进程跟随调度器实际加载的代码分支。

需要自动处理异常时，在现有批量配置设置 `agent.retry_issues: true`。
每集最多额外进入一次原生修复流程，已通过集跳过；调度器在启动前保存
`issue_retry_started`，重启和工具交接不会重新发放这次机会。正常 `deferred`
仍按原剩余时间续跑，不计作新的修复。任务沙箱配置的
`resume_session_on_retry: true` 保留原 Agent 会话，`timeout_seconds` 限制这次修复时长。
排队等待共享模型空位的时间单独累计为 `model_wait_seconds`，不消耗这次操作的
剩余时长。已消耗的创作/工具时间和重试次数保留，排队仍能响应暂停；实际模型
会话继续受原时间片限制，不能因等待而获得更多拍摄次数。
已有视频、输入修复额度和质检口径均不变。默认不开启自动返工。

只为特定执行终止续接时，可配置 `agent.retry_reasons` 为允许的完整终止原因。
它在实际调度时检查当前结果；已通过、内容验收未过或连续无进展的任务可以跳过，
无需为扩大操作时间重跑整份候选名单。未配置时保留原有显式返工行为。
已核对当前素材和未用权限、需要跟进共性接口修正的章节，可列入
`agent.retry_chapters`。它与终止原因筛选取并集；单独配置时只续接所列章节。
已经通过或已经使用本批续接机会的任务仍跳过，次数与媒体历史不重置。

角色状态图由素材工具按角色最多三路并行生成；每个角色的主图、闭合面罩图、
表情图仍按依赖执行，各角色独立使用原 600 秒工具上限。共享的缺失穿戴物先
完成一次生成；某个角色失败不删除其他角色已经完成的图片。宿主可以在原有
一次续跑额度内自动继续经过原文核验的未完成素材步骤。

`input` 修复支持 `phases.characters.<name>.reuse_asset_id`，直接使用该角色
已登记且有图片的状态；不能同时传入新的外观/服装字段。复用仍经过原文、实际
图片及请求校验，保留原片段时长与额度。未完成的素材使用原决定 `resume:true`。

修复批次可显式配置沙箱 `complete_started_repairs: true`：已提交且成功采用的
修复即使在 Agent 时间窗口结束后才完成，也由宿主继续执行一次正常渲染和验收。
不会增加 Agent 思考时间、拍摄次数或输入修复次数；暂停和无有效修改仍停止。
默认的整集截止时间行为保持原样。

审核模式独立于 H3 服务地址解析：显式 `NOVEL_REVIEW_MODE` 优先，其次小说的
profile 配置，最后使用流水线已有的 `defaults.repair.review_mode`。指定 H3 池不会
跳过审核配置。报告保存实际 `review_mode` 和审核版本；缓存、保留片段和最终验收
只复用同一方式的当前结论。模式不同或缺少记录时须实际复审，单段 `keep` 不能给
未检查的其他片段补上整集认证。批量精判始终保留自身的 verify 方式；旧队列记录
不能覆盖当前认证结果。这些检查不会自动重开已停止的集或增加拍摄额度。

当前 DS 的 vLLM Anthropic 接口不读取 `thinking` 及其 token 预算。该任务通过
`chat_template_kwargs: {"enable_thinking": false}` 配置，使用现有 CLI 的
`CLAUDE_CODE_EXTRA_BODY` 传入实际请求，同时设置 `max_thinking_tokens: 0`。
已用当前镜像捕获真实请求并做 DS 修复回放；仅设置旧的 1024-token 预算不足以限制
这个端点的思考。此配置不改变共享服务或其他任务，也不替代独立验收。

代码位于独立工作树而运行配置仍在原项目时，用 `--project-root /运行项目目录`。技能可从代码工作树加载；用 `--output-root /独立产物目录` 指定产物位置。`status` 只读取状态，不启动沙箱或任务。

## 验收与已知边界

技术通过、语音门通过和内容审查通过分别记录。Agent 不能自行把未解决问题标成通过；实际检查与当前产物决定 `finish` 结果。调用收到不确定提交结果时，继续沿用供应商原有恢复机制。

verify 模式的暂存成片须通过已有正式发布门，`finish` 才能返回通过并写入成功清单。
精判仍有明显问题时，返回 `publication_gate` 和具体片段，交回 `apply` 在现有额度内
处理；不能用上层可选问题标签绕过原始精判。成功后沿用正常发布和旧成片备份流程。

当前素材和计划匹配、整集技术检查失败时，黑帧、长时间冻结、长静音及静音占比问题
会进入 Agent 证据。Agent 可检查相关视频、已有音量/语音证据，明确提交需要处理的
片段，再使用现有修复额度。为定位问题展开的其他正常片段不要求逐一提交 keep。
分辨率、编码或封面失败不由此获得重拍权限，过期技术报告也不能用于申请新拍摄。

输入重编译后若缺少 `prompt_h3`，Agent 可以通过 `edit` 补齐英文，仍按当前已采用
计划校验参考图、对白、说话者、声线和时长；已有英文时继续保留原有对比约束。
完整请求也不能把额外台词放进摘要或声景。没有英文的 `retake` 会明确要求先补稿，
不会把单纯换 seed 当作修好请求，也不增加拍摄额度。

`apply` 支持 `input` 决策：提交连续原文引用，以及本段地点、光线、穿戴等已有字段的修正，或当前章节的角色阶段卡。主机核对原文后使用现有绘图与编译能力修复依赖段，保持对白、动作、机位、时长、生成历史和视频次数上限。阶段台账归本集，原书素材保留；每个目标最多两次输入修复。仍需生成与独立复审，不能将输入已修复当作成片通过。

`input.locations` 是“场景名 → 空场景描述”的映射，可为本集新增或重画场景图。与 `shots[].location` 配合选择需要的场景；新名称只追加到本集的 Bible，原书不变。场景变体记录在本集 `phases.json.locations`，编译器按章节绑定新图及描述，继续使用原有绘图服务、画风、画幅和空景检查。

已采用的 Agent 分镜可包含没有场景参考图、也不在素材库中的场景。只要地点未改变，
输入重编译保留这一选择，继续更新人物、道具及其绑定；不会强制查找或虚构一张场景图。
若自由场景标签与唯一已选场景卡名称不同，则沿用那张已登记卡的绑定，分镜场景名保持。
显式登记的新场景卡仍优先绑定；更换到未知地点或原引用也未登记时仍拒绝猜测。

输入重编译必须得到与当前输入匹配的英文；翻译拒绝时，具体来源冲突或格式错误返回
给 Agent，旧英文仍非空也不能被当作本次翻译成功。穿戴物模板使用物件本身的设计，
其他衣着保留人物卡约束，钱袋等配件不会被统一描述成替换整套服装或盔甲。

定点追加输入修复使用原 `repair_budget_grants.json` 中目标片段的 `input_limit`，
未指定的片段继续继承 `*`，仍受最多两次输入修复的硬上限。读取状态和实际执行使用
同一额度计算，原尝试记录保留；该能力本身不会给任何片段自动增加额度。

尚未采用的 source 草稿也可申请缺失角色和场景。宿主先核对原文，再用现有绘图服务
生成并检查实际图片，导出新的素材编号，随后由作者绑定草稿并重新检查；补图本身
不采用草稿或启动视频。素材登记在本集资料和按实际画风区分的共享缓存中。
人类、动物和空场景各自按适用的外貌/渲染要求检查，姿势和临时持物不成为定妆照的
强制内容。检查器修正后，旧图片拒绝可复查同设计同画风的已存图片；原文拒绝及当前
版本的图片拒绝继续停止，原输入修复次数、续跑次数及拍摄次数保留。

输入修复现在记录具体失败步骤、原决定和已完成的英文。服务错误保留为未完成操作，`status.input_repairs` 给出一次 `resume_action`；续跑复用已完成图片和匹配的英文，不增加视频额度。已成功的相同修复返回已有结果；同一批相同换装合并处理，因换图而失效的旧英文编辑返回 `deferred`，不再在素材已写入之后使整批报错。正常语义修改仍受 `input_limit` 约束，续跑也有一次上限。重编译的姿态、面罩检查跟随 `NOVEL_PLANNER_ENDPOINT`，未指定时保留原本的本地端点。

参数结构在去重、创建修复回执、调用模型和绘图之前检查，错误通过 `argument_errors`
指出字段及合法格式/范围。单个角色阶段对象由宿主转成单项列表，两种写法按同一
效果复用；不会另花一次额度或重画。穿戴关系保留 `{角色: 道具}` 的归属，字符串
不能靠程序猜穿戴者；普通衣着与身体特征分别写在阶段的服装/外貌字段。
旧错误参数不会再被当成可直接续跑的服务中断，已有回执和计数保留。只改错误信息
而没有实际修复不会重置停滞次数；同批中其他有效修复仍可正常推进。

`status.remaining_input_attempts` 和 `status.remaining_rechecks` 展示当前片段的真实剩余
次数，减少根据历史报错猜权限。旧 `tool_error` 沿用现有规则不计入输入尝试；缺少
原决定的记录不再给出无效 resume，而是明确现有的一次修订机会。已经发布的输入
修改只能续接自身的收尾；不同的修改须使用正常剩余额度，不能仅替换旧回执中的
决定后假称已经应用。

`accept_risk` 接通已有预渲染风险选择，只能确认当前片段确实存在的 `wearer_card` 或
`card_people` 风险，记录理由并受剩余拍摄预算约束；它不能修改剧情、素材或媒体验收。
`keep` 只用于已存在的当前视频，未拍片段不会消耗复查额度。

台词校验统一编译器已有的全角/半角标点口径，改词、换说话者和改变句子标点含义仍被拒绝。返工证据使用同次抽帧清单并保留时间，旧审查缺少清单时重新提取当前视频，避免漏掉末尾动作或带入旧抽帧。

ASR 保留原始识别与专名纠正记录，带入小说纠错表、人物、地点和道具词表。模糊纠错不替换另一个已登记名字，也不靠消耗邻接词补出漏掉的名字。识别文本不是独立听音证据；客户端保留原音频供核对，语音门与内容门仍需分别通过。

首次完整实验使用《美漫》第36章原文，自主产出14段、约152秒成片。技术与正式语音检查通过，内容审查13/14；一段胡须差异在三次主视频额度后仍未通过。该样本说明整集 Agent 工作方式可执行，尚不能证明所有章节质量或速度稳定。

Claude Code 是运行器名称，实际模型由沙箱配置决定；该次实验使用现有 Qwen3.8-Flash-Next。

## 已采纳镜头的输入修复

`action=input` 可以按原文修正入镜人物、群演、听者、动作归属和声景。`speaker_map` 显式纠正原文能核实的说话人错误，保持对白文字、发声方式、切点和时长。缺失的具名人物或实际说话人可通过 `characters` 申请卡片；已有角色的服装状态继续使用 `phases`。

宿主先核源，再审核实际图片，登记章内素材并重编译受影响片段；候选失败恢复原有剧本、计划和身份元数据。群演不强行注册成另一个主角。`status.repair_capabilities` 列出当前可执行字段，旧会话的停止结论不能覆盖这些能力和当前额度。

新恢复轮次的额外拍摄由 `grant_conditional_extra` 登记，必须有明确授权和理由。同一轮登记幂等，旧授权保留；有未用额度时沿用现有额度。新资格先允许准备，只有有效修复和实际输入预检通过后才激活拍摄，重启不能再次充值。

## 自动返工证据

`render` 继续逐段执行原有独立审核，但只为待处理的 `attention_clips`
展开完整请求、帧和语音证据。已匹配当前请求、选中视频和审核记录且通过各项检查的
`retained_clips` 保留简要状态，不要求 Agent 重复写 keep 决策。完整剧本和全段摘要
保留上下文；显式 `review` 仍可导出整集详细证据。缺失、过期、失败和混音版本不匹配
的记录仍完整呈现。此调整不改变验收标准、审核覆盖或拍摄预算。

角色外观说明与审核实际展示的卡绑定：明确选中的基础卡或阶段卡优先，不能把整章
最新阶段的衣着套到另一张卡上。缺少可用明确引用时，图片和文字一起使用章节默认
阶段。原文和本镜事件仍用于独立核对所选状态是否正确。

正常审核和修复审核共用上述选卡及描述规则，避免一个入口看实际卡、另一个入口
又套用章节默认阶段。修复扫描器仍保留自己的问题范围和图片数量限制；这项复用
不把两个入口视为完全相同的审核实验，也不自动重审已停止的集。


## 两个模型并行负责完整章节

同一个Conductor通过`agent.model_configs`将已分配的模型端点映射到各自的Agent配置文件。
`novels[].planning`分配章节宿主容量，`resources.planning_models`限制共享模型调用并发；
准备、编剧、输入检查和审核使用选中模型，H3翻译/请求检查可由该模型配置显式指定。
Qwen作为主Agent时不能继承DS的模型名、凭据变量或审核端点。

```json
{
  "planning": {"deepseek": 8, "flashnext": 4},
  "agent": {
    "input_mode": "auto",
    "parallel": 12,
    "normal_parallel": 4,
    "config": "runtime/ds-agent.json",
    "model_configs": {
      "deepseek": "runtime/ds-agent.json",
      "flashnext": "runtime/qwen-agent.json"
    }
  }
}
```

新章节按尚有容量的模型分配，归属写入现有章节状态。续跑保持原模型、会话、工作区和
拍摄记录，已经记录的DS拒绝回退可继续归入Qwen。正常准备和首次生产至少获得
`normal_parallel`个可用位置；没有正常工作时可用于修复。某模型的旧会话名额已满时，
另一个模型的剩余位置仍可领取新章节。正常任务转为显式返工后释放正常保留名额。
共享调用额度包含辅助调用，不是每种角色各有一套额度；修改Qwen总并发时，也核对
`h3_preparation_parallel`，防止翻译辅助配置仍把它压回2。
