## 2. 三组代码改动

**上游规则。** 普通规划、作者分镜、导演拆镜和局部修复共用内容边界：可以设计机位与必要反应，不凭空增加装备能力、特效、关键物件或剧情动作；结束状态写结果，物理音效必须有来源。没有按“电流”等词做删除黑名单。

**动作交接。** 打包在现有 clip_plan 中保留逐阶段 `action_bindings`，不把动作列表拼进中文事件。最终成稿器据此核对正文遗漏，动作变化也进入现有编译失效依据。旧计划从原剧本读取动作时按当前阶段 index 寻址，保留 origin_index 只作追溯，避免拆分后的原编号误配。

**一次成稿。** `application/rendering/h3.py` 读取本镜原文、有效中文分镜、源阶段的穿戴/物件绑定及实际图片。显式传入 native/silent_visual 和每镜原生对白列表；后期心声即使仍出现在原文/动作证据里，也不允许变成原生对白。只给本镜所引原文；不把未切段的原始大阶段画面重新当作当前片段的导演稿。模型一次返回按时序写的镜头、物理声景及未解决的事实冲突。语气紧随对白标记进入同一正文。模型回复残留中文时整份退回重写，删除了程序静默剥掉中文特征括号的旧处理。程序只绑定准确台词、声线、参考标识、时长及既有格式；不再追加修复备注、语气和默认环境音。

H3 正式批量入口、准备、局部修复、原文复核及单卡修复均传入 episode 上下文。读取不到当前图片时失败，不降级成仅凭名字猜图。Agent 的证据包含与普通生成相同的内容归属规则。

**原有修复衔接。** 成稿报告事实冲突时保留旧请求，不带着猜测放行；准备记录保存片段和对应阶段的问题，下一次准备跳过旧的“源剧本通过”缓存，将疑点交给现有源审核。只有原文证据确认的问题才进入原来的补丁流程，沿用准备轮次上限。

新规则进入现有编译版本，emotion 的改变也会让旧英文失效。没有重置视频次数、缓存目录或历史记录。历史小说的自定义画风未覆盖。

## 官方指南核对与手写示例（提交前补记）

随后核对 MiniMax 官方 h3-prompt-writing Skill 和 Ref2VA 指南，确认两点：必要参考特征跨定义、保留说明和正文重述有用途，不能一概当冗余删掉；与动作同步的声音应留在正文，overall_soundscape 汇总全片声景。当前代码的“物理声音全部只写 soundscape”要求仍待纠正。本提交保存现状，不表示已经全面符合官方指南或画面问题解决。

用户另行授权将聊天里的示例直接译成英文生成一次，产物为 `outputs/meiman-official-example-20260930/`。该手写请求绕过自动改写，保留相同三张图片、声线、12 秒、768p、9 个采样点及 seed 1200720684。成片已完整解码。0.5、3、6、11 秒帧均可见金色细线/机械连线；席勒肩部还出现参考图没有的机械部件。最终请求没有电弧、电线或机械义肢要求，三张实际参考图也没有对应连线。输入图片预处理仅做方向校正、等比缩放及 JPEG 编码，没有画线操作。

这支持“可见异常首次出现在生成结果”，不能证明 Turbo、某个形容词或某张参考图是唯一原因。参考外观串用、模型/采样偏差及该 seed 的影响仍待区分。检查格式正确不能保证排除这类偏差；本轮不再追加重拍或扩展实验。
