最新执行边界（2026-10-07后续确认）：使用 main 的标准批量生产入口，正常准备与
生成独立于Agent。`thin_batch --stage prepare --workspace-index ... --first-pass`
在现有章节工作区中补齐正常规划、素材、H3请求，并写`batch-production.json`；
标准生成批次只消费就绪回执，`workers=0`，实际并发仍受全局H3上限控制。已拍片段
不在首拍批次重拍，正式审查交给独立`batch_review` Agent。拍前的明确异常也在这条
独立异常队列处理，不占用主生产宿主。下文的逐章Agent宿主方式是此前阶段的记录。

工作区索引沿用每章的本地Bible、素材绑定、视频和历史，并保留原始章节锁。原生
计划一旦产出，就按已采用计划交给Agent；不能误当未采用草稿或重新采用旧英文输出。
审修接收到新的生产结果时仅使用未消耗预算，不把Agent自身补拍当作新生产交接来续命。

同日文字调度更新：输入异常优先进入100任务池；Agent结束会话并交给宿主工具后，
该宿主继续持有章节锁但释放文字派发名额。修好的缺首拍输入交回标准准备，不在Agent
中重新跑正常生产。各模型实际请求仍共用DS8/Qwen4；等待视频不阻塞其他章节的文字
修复，排队中的首次生成优先于补拍。历史失败、剩余时间及拍摄计数不因换调度重置。

续章沿用已经执行过的路径，保持小说ID、既有人物ID、原文索引和产物历史：

| 顺序 | 现有入口 | 实际交付和后续消费者 |
| --- | --- | --- |
| 1 | 原文增量登记 | `novel.json`和原文偏移；旧章正文保持一致 |
| 2 | `lean_bible_thin.py` | `lean/extract/ch-NNN.json`：摘要、称谓、在场、外貌、变化、地点；全部新章齐全才能归并 |
| 3 | 现有merge沙箱 | 候选表与既有名单一起归并；输出人物、别名、未决项和阶段建议 |
| 4 | 增量采用读书名单 | 合并`reading_cast.json`的人物、地点及实际出现章节、别名并播种账本；地点追加到Bible且保留旧资产编号，叙事描写只作原文证据，不直接当空场图提示词 |
| 5 | `story_pass_thin.py` | 按章整理实体/状态账本，生长人物与场景资料，写`recap.json`和卷级摘要；检查实际章覆盖 |
| 6 | `thin_batch.py --stage plan` | 依据完整读书资料生成分镜、来源与说话人绑定、片段计划；长对白走已有压缩流程 |
| 7 | `build_cards_thin.py --review` | 只补计划实际引用的缺失人物、场景和道具图，检查实际图片 |
| 8 | `prepare_h3_book.py` | 来源审核、素材绑定、H3英文和请求检查，写逐章准备状态 |
| 9 | 现有生成与审修宿主 | 正常执行已准备的script；失败交给Agent处理具体异常，保留原文和预算 |

初读缓存和种子圣经已齐后，沿 `setup_book_thin.py` 的现有出口进入普通逐章规划：

身份或资料问题留在涉及的章节处理，不要求全书台账全部通过才允许其他章节开工。
已经完成过资料预扫或增长的批次使用 `--no-grow-bible` 跳过重复预扫；这不关闭规划器内部
对本章缺失演员的按需补齐。H3 文本规划显式设置 `NOVEL_CLIP_SECONDS_MAX=15`，
已成剧本可用现有本地打包器转成15秒片段，不因换档重新编剧或重置拍摄次数。
按章增长会复用相同原文的扫描结果；资料库变化只补实际缺项。身份复核复用当前
候选与相关资料对应的有效回执，无关人物新增不重开审核。相同输入的有效失败没有
可用新修订时保留卡点；技术未完成不当作内容失败。模型额度耗尽时停止批次新派单
和第二遍重试，保留已成计划和在途任务的实际结果。
先尝试正常分镜和H3准备；Agent接管正常阶段记录的异常。
