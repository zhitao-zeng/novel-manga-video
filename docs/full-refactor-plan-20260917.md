# 全部剩余重构实施计划

本计划落实用户“制定完整计划，最好都重构”的要求。范围采用 [重构总清单](refactor-inventory-20260917.md) 的 R01–R12，**全部纳入交付，包括此前可选的应用归包、前端分文件和测试文档整理**。本文件是实施计划，当前尚未执行这些代码改动。

## 一、目标与当前基线

最终让“改一个业务意见”有明确落点：

| 要改什么 | 唯一主要修改位置 |
|---|---|
| 人物身份、动作目标、对白归属 | story 的共享规则 |
| 小说解读、规划请求、预算和原文校验 | planning；模型调用由 application/planning 编排 |
| 构图、听者、镜头表达 | story/framing 及相应表达函数 |
| 中文/H3 提示词与主体编号 | story 的编译/请求表达模块 |
| 该保留、改词、改分镜还是重拍 | repair 的决策模块 |
| 素材缓存、字幕、音轨评价和后期 | media 对应服务 |
| SD/H3/图片后端的请求与任务协议 | providers；文本模型传输归 llm |
| 小说、资源、画幅和运行路径配置 | 入口配置组装；下游消费明确参数 |
| 派单、写回、历史、发布、启动停止 | application 的相应流程 |
| 费用和产出统计 | reporting；看板与命令行消费同一结果 |
| 看板布局和图表 | dashboard/templates、dashboard/static |

2026-09-17 重新核对的实施起点：

- 当前仓库 `main@0c02ac9`，比本地记录的 origin/main 领先 5 个提交；未联网更新远端引用。
- 工作树有两项其他任务的代码修改：`scripts/build_h3_prompts.py`、`src/novel_manga/media/analysis.py`；另有本任务的总清单文档。
- 无对白镜头运行 ASR 是为发现曾经出现的胡乱说话；检测保留，提示词由另一任务继续调试。撤回的 F05 不作为优化目标。
- 当前诸天暂停标记存在。实施和部署均不得自动解除。
- 已有审查证据覆盖 236 个生产 Python 文件；之前 894 项回归的通过记录只说明旧基线，不能当成本轮改完的验收。

“全部重构”指完成 R01–R12 的剩余职责整理，不重写已经独立的并发池、队列、基础质检和 FFmpeg 算法。人物库重建、历史剧本修正、整集叙事检查、提示词效果实验及新增生产策略不加入本轮。

## 二、最终目录与依赖

下图是仓库根目录下的目标职责；具体文件只在职责确有分离价值时建立。

```text
scripts/                         原有命令名、参数、退出码；只做启动和参数转换
src/novel_manga/
  application/
    planning/                    新书准备、读书、章节规划和请求编排
    identity/                    章节身份资料、账本读写与实体解析编排
    packing/                     加载本集资料、调用编译、写片段计划
    rendering/                   ThinMediaRunner、一次生成执行、报告写回
    review/                      取证、模型调用、复审和补查编排
    repair/                      修复执行、派单、候选接受、历史和发布
    production/                  批量调度、资源配置和子进程管理
    dashboard/                   状态读取、HTTP 服务和刷新编排
    configuration.py             已有文件/环境/参数的组装与运行路径
  story/                         身份、动作、对白、构图、场景和请求表达
  planning/                      请求字段、预算、归一化、验证和修订决策
  entities/                      实体定义、证据规则
  repair/                        修法决策和内存候选
  review/                        审查定义、证据合并和判定
  media/                         资产、生成、缓存、分析、字幕和后期
  providers/                     图片/视频接口、任务、下载和并发池
  llm/                           文本模型端点、传输、响应解析
  reporting/                     用量、费用、产出和统计定义
  models/                        现用小说/人物库/剧本/资产数据类型
  dashboard/
    templates/                   页面模板
    static/                      现有 JavaScript、CSS
    ...                          已有文件与快照缓存
  config.py                      现有配置数据定义与校验，保留职责
  ingest.py、splitting.py、...    已有独立能力，按需更新导入
tests/
  support/                       共享夹具与冻结输入
  ...                            按业务领域组织的回归
experiments/                     A/B、测速、样片和实验专用历史实现
configs/                         继续使用现有配置文件
docs/architecture.md             唯一当前架构说明，日期文档保留作历史
outputs/                         原有产物、视频、状态和记录，原地保留
```

依赖规则：

1. 命令入口调用 application；application 调用业务服务、共享规则及基础接口。
2. story、planning 的规则、repair 的决策不读生产目录、不请求模型、不导入 application。
3. media 的生成执行可以调用 providers；分析和质检不调用生成、调度或发布。文件选取及流程写回的所有权不因搬目录改变。
4. src 内部不导入 scripts，生产代码不导入 experiments；应用子流程不得通过导入上层总控发起下一轮。
5. 内部旧模块路径统一替换并移除，不留纯转发兼容文件。scripts 下保留的是用户仍在使用的命令入口，其参数和子进程识别方式保持稳定。
6. 不把所有 dict 改为新对象。沿用 SceneContext、ResolvedScene、ChapterIdentityData、RenderContext、RepairProposal；只补足实际交接需要的参数和类型。

## 三、数据与行为边界

保留 `chapter_script.json`、`clip_plan.json`、ASR 记录、任务 sidecar、修复历史和状态文件的现有落盘格式及路径，不引入新剧本格式、数据库、队列、迁移框架或特征开关。

角色/卡片编号、片段 ID、原文定位、拆分关系、选择的素材、实际生成次数、重试预算、候选目录、发布顺序都进入回归对照。纯职责调整不得改变模型请求、提示词、模型参数、并发和缓存选择。

生成前的候选检查失败不派视频任务，也不消耗一次生成次数；已经实际生成的素材即使后续未通过质检或未发布，仍按原机制记录生成次数与用量，不能因拒收而抹去。

需要有意改变行为的只有当前清单内确认的问题：F01 请求声明误报、F02 改词后派生字段不同步、F03 Seedream 场景画幅、F04 身体卡缓存失效，以及 F06 费用统计范围。这些修复单独提交，记录允许发生的差异；其余对照必须一致。

无对白 ASR 的触发、阈值、识别方式、小说级语音门和旧素材重查范围继续采用正在调试任务落定的行为。本轮可以拆清函数职责，但不跳过检测、不清空旧 ASR、不发起历史补查。

## 四、实施批次

### 第 0 批：工作树与对照基线（R12 的基础部分）

1. 实施时从最新核对后的当前主线创建 `codex/full-pipeline-consolidation`，在同仓库的独立工作树完成；不把当前其他修改 stash、覆盖或混入提交。
2. 记录提交基线、两项在改文件和现有暂停状态。其他任务的提示词/检测版本落定后，更新对应回归输入；不把一份仍在变化的工作树当最终验收版本。
3. 对已有五章、25 段跨流程样本核对可用性，复用现有 service_contract_cases、场景、打包、媒体和重试夹具，建立统一回放入口。大视频放在本地测试产物目录，Git 只收小型必要夹具。
4. 冻结规划/修段/中文/H3 请求、解析结果、修复决定、片段变更范围、缓存选择、生成调用次数、历史写入顺序及状态快照。
5. 冻结现有配置的有效值和来源；凭据只记录变量名，不进入快照。对状态文件的比较使用现有内容，不新增生产指纹机制。

**通过条件：** 同一基线的回放重复运行一致，测试不连模型服务；五类待修问题有明确的前置失败用例。

### 第 1 批：请求、对白、画幅和缓存交接（R01–R04）

**R01：H3 请求。**

- 先以另一个任务落定的提示词版本为依据修复声明句式与校验器的冲突，提示词效果不在此处重调。
- 把主体/参考图/音频编号、对白绑定和 H3 请求结构放在共享的请求表达模块。现有中文文本输入确实需要解析时保留一个明确解析器，不在不同流程再写一份正则。
- 模型翻译与备注翻译留在 application，文件更新留在原流程时机。生成器与校验器共用声明规则，但仍检查最终实际请求中是否有未声明主体、编号不一致和错误发言绑定；不能只验证原始剧本而放过生成出的请求。
- 不为了改目录使旧的已通过素材批量失效，不统一重翻译全部历史提示词。

**R02：对白与音频。**

- 拒绝后的台词改写通过一次明确的对白更新操作同步 `lines`、`spoken_text` 和相应 `dialogue_bindings`。只更新原本受影响的片段，保留说话人、原文地址和拆分关系。
- 明确“音轨/识别结果获取”和“按当前对白计算评价”的两个阶段。相同素材和识别参数复用识别结果，台词改变时重新计算相关评价；按现有缺失信息处理方式消费历史记录，不臆造缺失证据。
- 字幕与语音检查读取同一份当前对白。无改动时保留请求和缓存；评价重算本身不增加视频生成次数。
- 意外语音检测继续运行，ASR 次数与正在调试任务的认可基线一致。

**R03：画幅。**

- 先修支持的 Seedream 图片通道横屏场景尺寸。再用显式图片/视频请求选项替代 client.post 方法替换和线程局部画幅补丁。
- 资产层决定人物卡还是场景卡；供应商构造各自的 `size`、`aspectRatio`、`ratio`、`resolution` 字段。不再根据服务内部全局状态猜画幅。
- 图片请求、视频请求与参考素材顺序独立；模型限制、人物卡竖屏策略、横竖屏成片参数不变。

**R04：资料和缓存。**

- 先把身体映射缓存限定到一次明确操作，修复同章账本更新仍取旧卡的问题。
- 复用已有章节身份资料对象，补入派单这一轮需要的计划、反馈、预算和发言证据；稳定扫描一次读取、多段复用。
- 写回计划、身份、账本、资产或反馈后，后续处理明确重新加载；下一轮扫描也重新取得资料。保持逐段容错和旧素材保留行为。
- 不引入跨进程常驻全书缓存，不靠添加新 hash 判断所有文件是否变化。

**通过条件：** 五章样本和对应真实回归通过；无修改的模型请求、缓存和次数一致；只有 F01–F04 对应的预期输出发生变化。资料读取减少用确定的读次数验证，不预先宣称整条产线快几倍。

R01 或 R02 涉及的文件仍在另一个任务中调试时，先执行本批独立的 R03/R04 和后续独立工作。相关交接未完成时，不宣称本批全部验收通过。

### 第 2 批：配置与文本模型调用（R05–R06）

**R05：配置组装。**

- 小说列表、标题、章节范围和资源分配从现有 pipeline 配置取得；画风/画幅/小说策略继续从 profile 取得；凭据和端点采用现有环境入口。
- 默认值、profile、环境、通道和 CLI 不机械采用一条新优先级：先冻结各字段当前优先关系，再把同一关系集中到组装函数。新文档明确字段来源，避免重构暗改实际参数。
- 工作目录/配置目录通过运行路径对象传入，不把安装位置当产物位置，不固化个人磁盘路径。
- 保留当前已部署路径的有效值、已有并发池目录、H3 修复默认参数、暂停和恢复语义。移除导入期修改环境的行为；子进程环境由启动步骤构造独立字典。
- 看板和 CLI 读取同一小说登记及三条流程快照；新增测试小说只改配置即可出现。

**R06：文本模型传输。**

- 建立 llm 包，迁入现有 JsonEndpoint、请求发送、流式响应重建和 JSON 响应解析。更新人物库、规划、身份和审查调用方，完成后移除旧 model_client 模块的内部入口。
- 请求字段、端点顺序、超时预算、截断重试、认证和请求用量记录逐路径对照；不能把人物库和规划的策略差异悄悄归一。
- 提示词、语义反馈与修订次数归调用流程；视频任务仍由 providers 管理。审核过滤探针继续使用其平台协议，不混进普通文本生成接口。

**通过条件：** 三本书及测试新书的有效配置一致；不同书/15 秒/30 秒上下文交替不串值；流式、非流式、超时、截断和备用端点模拟返回的请求/调用次数与原逻辑一致。

### 第 3 批：规划职责、统计和历史依赖（R07–R09）

**R07：规划校验。**

- 在现有 validate_and_normalize 内按顺序抽出字段整理、原文定位、对白规范化、说话人分组/听者构图和时长校验。
- 动作与别名继续使用已有 story 规则。构图函数只决定表达，不重新认人、猜目标或换说话人。
- 完整规划与修段保留各自必填字段和数量限制；共用字段定义不等于同一个请求。
- 保留诊断文本、编号及模型修订决策。出现需要改变规则才能“统一”的分支，记录为后续策略问题，不在本批合并策略。

**R08：统计。**

- reporting 从现有 task/usage、当前报告和修复历史得到统计；区分当前选中素材、可追溯累计生成、最终成片和净增交付。
- 用已有供应商任务 ID 和通道识别同一任务，不把多个报告引用同一任务重复记账；缺少任务 ID 时按已有记录能证明的范围统计，并显示不足。
- SD2.0、SD2.5、H3、图片分别统计，混合模型/分辨率分开计算。本地 H3 不套付费 SD 单价；本地算力成本没有记录就写未统计，不称为零成本。
- 时长区分生成素材与最终成片；token 区分模型实际 usage 与缺失记录；缺价格不推断金额。历史清单不当全书验收数，当前交付判定算法保持原样。
- CLI、CSV 和看板共用统计函数；保留现有持久化报告格式。展示口径变化在文档和界面说明，用户能看到覆盖范围。

**R09：旧模型与实验边界。**

- 从当前 models.py、production_models.py 按使用关系拆出 source/bible/episode/assets 等模块，更新内部导入，不保留旧路径聚合导出。
- 以字段引用闭包判断现用类型：EpisodePlan 当前仍引用的 showrunner/contract 等字段及其类型必须保留格式，不能因为名称像旧流程就删除。
- 只把生产无消费者的模型、整书资产工厂和历史运行算法迁到 experiments/legacy；仍有用途的诊断工具及其依赖一并归类。
- 旧 shell 产线接管操作独立核查。如果还有挂起/在途任务依赖，先保留唯一仍有效的接管实现并与正式执行模块分离；全部接管完成后移除一次性入口。历史证据、任务步骤和缓存读取继续可用。
- 每个保留的历史依赖写清实际消费者，不留下无说明的兼容壳。

**通过条件：** 规划结果、JSON 字段与报告序列化对照不变；费用覆盖缓存复用、归档素材、混合后端、缺 usage/价格的场景；实验隔离后新书初始化、资产和诊断工具仍可导入运行。

### 第 4 批：应用归包与前端拆分（R10–R11）

**R10：应用归包。**

- 首批搬入规划、身份、打包、渲染、审查等执行服务；再搬调度、修复管理、状态服务。按依赖顺序一次更新内部 import、测试替换点和子进程调用。
- 原 scripts 命令只解析参数、定位项目运行目录、构造配置、调用 application、输出结果。保留 ThinMediaRunner 和统一 pipeline 管理方式，不给每个服务新增命令或进程。
- 保留所有仍受支持的运维命令。其业务函数迁入对应应用模块；删除只有内部调用方的旧辅助脚本。
- 缩减 runner/packing 的纯转发方法，业务调用显式访问服务；不使用多重继承、动态补方法或隐藏回调重组流程。
- 更新 pyproject 的包资源收集。共享服务在没有 scripts/experiments 路径的环境也能导入，命令仍可从原项目启动方式运行。

**R11：前端分文件。**

- 将 dashboard_ui 的页面字符串拆到模板/CSS/JS；现有 pipeline_dashboard.js 一并纳入 static，保留现有图表和文案含义。
- 状态服务显式加载包资源，提供固定的静态资源路径；保留 `/`、`/board`、`/status.json`、`/board.json`、`/runtime.json`。
- 前端消费后端统计结果，不重算一套交付/费用规则；轮询频率、后台刷新、加载/异常时保留旧数据的行为保持原样。
- 不引入新的前端框架，不增加手机页面工作。

**通过条件：** 旧命令帮助/参数/退出码通过冒烟测试；产线辅助模块不再留在 scripts 被反向导入；打包后的模板/JS/CSS 可加载。用冻结状态驱动真实本地页面检查进度条、柱状图、暂停、错误和空数据，JSON 与 CLI 状态一致。

## 六、验收矩阵

| 验收对象 | 必须覆盖 | 完成证据 |
|---|---|---|
| 字段与身份 | 山羊/物件目标、临时动物主体、空目标、自我包扎、画外目标、复姓/歧义别名 | 五章样本与已有 scene/contract/identity 回归，演员/动作不被新合并 |
| 对白与 H3 | 长台词拆分、画外音、发言编号、参考音频重排、拒绝改词、新声明句式 | 请求逐字段与文本对照；F01/F02 的修复前失败、修复后通过 |
| ASR 与字幕 | 无对白但胡乱说话、实际静音、普通对白、群聊、片尾；observe/enforce | 模拟 ASR 返回与固定音轨；检测调用/触发策略遵守认可基线 |
| 画幅和模型 | SD2.0/SD2.5/H3，15/30 秒，人物卡/场景卡，横/竖屏交替 | 完整请求 payload、参考顺序及上下文隔离对照；F03 预期差异 |
| 读取和缓存 | 同轮多段复用、同章资料变化、跨书、缓存命中/归档/缺失 | 读次数、选择路径、原报告与成片内容；F04 只更新应变的映射 |
| 重试与计数 | 次数耗尽、晚一次失败、提交不确定、修卡/改词、旧片保留 | 现有 16 组重试轨迹；供应商调用、槽释放、实际生成次数和历史一致 |
| 修复与发布 | 无改动、单段失败、候选未通过、拆分关联、cache-only、待发布 | 变更片段范围、候选接受、写报告后记历史的顺序；生成前检查失败不写回/不派单，已生成但拒收仍计生成 |
| 状态与操作 | 重复启动、停派后在途完成、暂停续跑、读取不推进、三流程过滤 | 模拟子进程/临时状态目录；CLI 和看板返回一致、状态文件不被查询改写 |
| 统计 | 本地/付费混合、重复引用、缓存、归档、缺 usage/价格、成片与素材时长不同 | 固定任务集可手算对照，覆盖范围清晰，不推算不可追溯额度 |
| 媒体合成 | 固定短素材、原字幕、群聊、横竖屏、片尾静音 | 真实 FFmpeg；分辨率/帧率/编解码/顺序/字幕一致，时点和时长差不超过一帧 |
| 依赖与发布包 | 无循环、无 src→scripts、无生产→实验、纯规则无 I/O/调度 | AST 依赖检查与无 scripts 路径的包导入/资源加载测试 |
| 新书与全链路 | 初始化、规划、资产、打包、生成模拟、审查、修复、合成 | 冻结模型返回的端到端回放及完整保留测试 |

比较仅排除时间、耗时、临时测试根目录等与业务无关的记录。不能排除模型请求、警告/决策、素材引用、路径含义、重试次数或缓存结果来制造“等价”。

测试不调用真实图片、视频、文本生成服务。使用现有项目 Python 环境；需要隔离环境时遵守工作区环境清单规则，不改其他项目环境。

## 七、另一任务的接入、部署与回退

### 正在调试的提示词/语音检测

保留另一任务对这两项功能的修改所有权。R01/R02 以其落定的提交或明确文件版本为接入基线；可在独立临时副本验证接口，但不把未经落定的调试补丁混入我们的提交。接入时查看实际差异、更新请求/检测回归，再完成同一 R 编号的验收。其他批次继续推进。

### 更新运行目录

1. 记录运行目录当时的 HEAD、未提交修改、管理器/看板进程及诸天暂停标记。独立工作树通过不代表运行目录已经更新。
2. 实际集成前再检查其他任务的新改动，保留其原状；先在独立集成副本验证，不用 reset/clean 清理工作树。与正在调试的文件有冲突时先完成确定版本的交接。
3. 合入时保留逐项提交。代码落地前停止受影响流程的新派单，在途工作按原机制完成；不停止无关小说/任务。代码迁移后不让旧进程继续从新目录动态加载一半旧、一半新的模块。
4. 更新完成后只重载受影响的管理/看板进程，恢复变更前应运行的流程。诸天保持暂停，禁止顺带规划、重拍或全书重查。
5. 核对预算、任务记录、所选素材、暂停和现有文件路径未被迁移/清零；验证命令导入、状态端点、页面资源和状态一致。真实生成不作为重构验收动作。
6. 记录 main/远端的实际同步情况。实施收尾时按照届时用户对 merge/push 的授权执行；当前这次计划制定不进行提交、推送或部署。

### 回退

每批保留可定位的提交边界。功能问题用修复提交回退；部署问题回到已验证代码版本或针对本批提交撤销，并保留其他任务修改。回退不恢复旧数据快照、不覆盖已经产生的生产记录、不清空缓存/预算、不取消暂停标记。由于落盘格式保持不变，不安排数据反向迁移。

## 八、最终交付与结束标准

- R01–R12 全部有代码结果和对应验收，R10–R12 不再以“可选”留空。
- 18 个提交单元或其更细的同范围提交；明确区分行为修复与等价重构。
- 当前架构图、目录/职责/依赖说明、配置来源及正式命令说明。
- 统一的请求、决策、缓存、状态和媒体回归，以及每类允许差异的证据。
- 干净提交与实际集成工作树的完整测试结果、部署记录、诸天继续暂停的核对结果。
- 历史依赖若因真实挂起任务需保留，必须完成隔离并列出消费者；不得留作无说明的“之后再看”。

全部达到后结束本轮代码整理，后续细节归回既有 R 编号。新增业务或新证据需要变更范围时单独说明，不把泛泛的“还能优化”继续追加为本计划未完成项。
