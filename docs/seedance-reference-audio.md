# Seedance 参考音频（实测记录，2026-09-05）

结论：`sd2.5` 的视频任务接口**接受参考音频**，用来克隆音色，不是播放参考内容。此前"接口不收音频"的判断是错的——那是照着我们客户端的代码下的结论，没有去试接口。

## 请求格式

`POST {base}/api/v3/contents/generations/tasks`，在 `content` 数组里追加：

```json
{"type": "audio_url", "audio_url": {"url": "data:audio/wav;base64,..."}, "role": "reference_audio"}
```

- `role` 必填。漏了会返回 `reference media mode requires audio role to be reference_audio`。
- 和参考图一样支持 data URI（base64 WAV，16 kHz 单声道即可），不需要外部可访问的地址。
- 可以和 `role: reference_image` 同时出现，互不影响。
- 其他写法都不认：`type: input_audio`、`type: reference_audio` 返回 `unknown type`；顶层的 `audio_url` / `reference_audio` / `audio` 会被静默忽略（任务照常提交并计费）。

## 实测效果

同一条提示词、同一句台词，只改参考音频。相似度用 CAM++ 声纹（`scripts/voice_consistency_thin.py` 用的同一个模型），对比对象是那段参考音色本身，0.55 以上一般判为同一人。

| 提交内容 | 与目标音色相似度 |
|---|---|
| 不带参考音频 | 0.44 |
| 2.1 秒的语气词「嗯」 | 0.44（等于没用） |
| 2.7 秒真实台词 | 0.60 |
| 12 秒真实台词 | 0.695 |
| 12 秒真实台词 + 角色卡 | 0.706 |

- **参考音频的长度和内容质量决定效果**：两秒的语气词毫无作用，十秒以上的连续台词能把音色拉到判定线以上。
- **克隆的是音色不是内容**：四条成片的语音识别结果都是剧本台词「我说过了这幅画不卖」，参考音频里的原话（「城南小树林我等你……」）没有出现。
- 参考音频可以直接从我们自己已出片的集里剪：把某个角色在同一集里的单说话人语音块拼到 10 秒以上即可。

## 顺带发现

任务查询返回里有 `usage.total_tokens`（5 秒 480p 一条是 48437），这是接口侧真正的计费单位。我们的 `.task.json` 边车目前没有记录它；记下来的话成本台账可以从"秒数"升级到"token 数"。

## 多说话人（2026-09-07 实测）

同一提示词里两个说话人、两条参考音频（沈玄川 12 s 男声、苏清月 12.3 s 女声）、两张角色卡，各出 8 秒。

| 变体 | 提示词里的绑定 | 音频顺序 | 沈玄川那句更像 | 苏清月那句更像 |
|---|---|---|---|---|
| A | 沈玄川→@音频1，苏清月→@音频2 | [男, 女] | 男声参考 0.67 | 女声参考 0.71 |
| B | 对调：沈玄川→@音频2，苏清月→@音频1 | [男, 女] | 男声参考 0.67 | 女声参考 0.76 |

- **多条参考音频都生效**，每个说话人各得其所，相似度 0.67–0.76，比单人测试还高。
- **`@音频N` 的文字绑定不起作用**：A、B 两版结果一样，模型是自己分配的，不看提示词里写的对应关系。两条参考互相之间只有 0.33，所以不是碰巧。
- 分配依据是"顺序"还是"按人物匹配"，用变体 C 判定：不写任何绑定、音频顺序反过来 [女, 男]。结果沈玄川仍是男声参考 0.689、苏清月仍是女声参考 0.753（这一版两句之间没有静音，按台词字数比例切开后各自算的）。**结论：模型听参考音频，按画面里的人物去匹配，顺序和提示词绑定都不起作用。** 异性别的两人段可以放心带两条；同性别的两人段模型只能靠猜，见 `docs/thin-pipeline.md` 角色音色一节的实测。
- 计费：8 秒 480p 一条 77,260 token，和 5 秒的 48,437 基本按时长线性。


## 本地 MiniMax-H3 的参考音频（2026-09-11 实测）

GPU052/GPU003 上自建的 `minimax-h3-ref2va-turbo` 同样接受参考音频，行为和 sd2.5 一致。

单人：同一段提示词、同样的参考图、同一个 seed，只换参考音频，成片基频跟着参考走。

| 变体 | 参考音色 | 成片基频 |
|---|---|---|
| 不带音频 | — | 188 Hz（自己编） |
| 低音参考 | 111 Hz | 121 Hz |
| 高音参考 | 286 Hz | 250 Hz |
| 低音 + 提示词写「用 `<Audio 1>` 的音色」 | 111 Hz | 123 Hz |
| 高音 + 同上 | 286 Hz | 250 Hz |

**提示词里点不点名 `<Audio 1>` 没有区别**，直接把音频挂在 `conditions` 里就生效——这正是我们管线送的方式（我们的提示词里根本没有音频标签）。

多说话人：拿雾月真实出片的双音色片段，按台词长度比例切段，用 CAM++ 声纹分别比对两条参考。

| 片段 | 两个说话人 | 结果 |
|---|---|---|
| wuyue_1013 clip_04 | 莱恩（男）、塞西娅（女） | 各归各位，0.67 / 0.48 |
| wuyue_1012 clip_06 | 同上 | 各归各位，0.75 / 0.64 |
| wuyue_1016 clip_01 | 莱恩、比尔（同为男性） | 莱恩那句更像比尔：0.76 对 0.46 |
| wuyue_1016 clip_04 | 同上 | 0.83 对 0.47 |

**结论和 sd2.5 相同**：模型按画面里的人物去匹配音色，不看提示词绑定；异性别两人段可靠，同性别两人段两人会合成一个嗓子。同性别对手戏要么接受，要么在打包阶段拆成各自的单人镜头。

（切段是按台词字数比例的粗略切法，很短的句子不可靠；同性别那三段的错配在 0.63–0.83，信号强到不像切法造成的。）
