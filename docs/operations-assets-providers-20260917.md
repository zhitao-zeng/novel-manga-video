## 1. 看板共用采集

`dashboard/files.py` 与 `dashboard_store_thin.py` 共用目录发现和未变化文件的解析结果。每次统计仍重新读取文件元信息；同次采集中，历史图表和库存统计共用章节状态，修复统计也使用同一个文件仓库。

目录缓存使用已有目录元信息，并包含子目录链接数，以识别本机文件系统同一时间刻度内新增的章节。文件内容变化在下一次采集被识别。控制器状态、暂停、在途和实时交付数不进入这一缓存，原有历史刷新频率和持久快照格式保持不变。

## 2. 资产职责

| 模块 | 职责 |
|---|---|
| `media/asset_style.py` | 每次建卡独立的 `AssetStyle`，建卡命令与渲染共用。 |
| `asset_prompts.py`、`asset_specs.py` | 提示词规则和资产说明字段，不请求模型、不写生产文件。 |
| `asset_images.py` | 原有图片缓存匹配、旧文件归档和一次生图调用。 |
| `asset_builder.py` | 指定人物卡与场景卡的建设；不再继承整书资产工厂。 |
| `asset_records.py` | 清单合并及已通过的参考图记录，保留原文件锁和格式。 |
| `asset_inspection.py` | 图片完整性检查、损坏处理和本地预览图。 |
| `asset_repair.py` | 被拒参考图的原有修法、重绘等待与已成功资产豁免。 |
| `assets.py` | 本集资产准备及原有重试编排。 |

移除建卡命令通过 `apply_genre` 修改模块全局变量的方式。自定义类型处理完后，下一本书使用自己的配置或默认值。Fast 模式仍只建设既定主卡，本轮没有增加表情卡。

旧整书资产工厂与当前选择性建卡共用提示词、说明字段和图片缓存能力；保留各自原有建设范围与生成顺序。

## 3. 开拍准备步骤

`prepare_h3_book.py` 保留原命令参数，只负责入口。

- `preparation_store_thin.py`：输入记录、原始备份、状态和续跑资格。
- `planning/preparation.py`：审查字段、证据约束和局部修复/整章重规划判断。
- `preparation_audit_thin.py`：原文审查、证据补正及问题单确认。
- `preparation_actions_thin.py`：准备计划、审查并修正、更新人物绑定、补卡、翻译和验收。
- `preparation_flow_thin.py`：依次执行步骤，管理原有子进程、暂停和有次数上限的重试。

已有视频和已归生产管理器所有的章节继续跳过。暂停停止新派单，已启动的章节按原机制完成；子进程继续启动同一个正式命令。

## 4. 供应商接口

`PhanRouterMediaProvider` 保持生图、生视频和调用参数，组合以下能力：

- `phanrouter_references.py`：素材上传/注册、复用、托管地址和内联参考素材。
- `phanrouter_images.py`：原有两类生图接口、轮询及续查。
- `phanrouter_video.py`：视频请求、任务恢复、轮询和费用记录。
- `phanrouter_tasks.py`：提交重试分类、结果解析和提交不确定记录。
- `downloads.py`：已有素材下载、部分文件和原下载重试。

保留横竖屏适配、音频和参考图顺序、各模型参数及现有侧车文件。提交不确定仍不会自动重复提交；下载失败仍复用已有任务。

本项纳入原工作树中 `phanrouter.py` 的两行修改：下载可显式使用另一个客户端。它用于 H3 的直连下载，原调用方式保持有效；其他会话的剩余修改不纳入提交。
