# 穿戴检查接线修复（2026-10-03）

问题：Agent 源模式直接给出英文，中文 `clip.prompt` 为空；旧检查从中文提取穿戴，因此读不到作者已有的 `shot.wears`。同时风险检查可以凭阶段资产的 `wears` 登记免检，覆盖实际图片不匹配的结果。

## 当前职责

- 现有 `clip_plan.json` 增加 `wears_bindings`，沿用 `action_bindings` 的逐镜地址结构：`stage`、`source_stage`、`wears`、`in_frame`。普通打包和 Agent adopt 共用 `story.scene.wears_bindings`，仅深拷贝已有决定，不新增穿戴推断。
- 检查优先读这份结构化数据。显式空列表、空字典和脱下的 `null` 不回填旧中文；只检查该阶段实际入镜的人。未带此字段的已有计划仍从原中文提取；已有 Agent 源计划中文为空时，直接读取当前剧本里对应镜号的已有穿戴字段，不修改或迁移历史计划。
- 参考图与装备描述交给原有图片判官；当前有效的 `matches` 结果可以解除阻塞，阶段声明不再是图片证据。已有明确风险接受记录保留原规则。
- 由共享渲染流程在资产准备、缺图检查之后统一发起穿戴核对，Agent `_runner` 不重复提前执行。缺图不提交给判官；同图、同目标复用原结果，图或目标变化重新核对。
- 单项模型或图片读取异常只保持该项未核实，不写成永久缓存的答案；其余片段继续执行。报告区分未核对、不匹配和看不清，检查服务恢复后可以再次核对。

未修改编剧、机位、最终 H3 文本、采样、重试次数或发布规则；不主动重拍历史视频。衣着时间线选卡和输入修复重新编译的问题另行处理。

## 验证

主线完整测试 1873 项、Agent 完整测试 2094 项通过。新回归包含真实 `adopt → run`、阶段 ID 不变而换图、空状态/脱下/独立空甲、同图复用、目标更新、判官异常隔离与恢复、缺图停止及显式风险接受。

冻结修复对照只新增九处逐镜穿戴元数据；程序断言模型请求、修复决策、镜头范围、历史与预算其他字段保持相同。模型、资产与视频生成边界使用模拟返回，没有请求真实图片/视频服务；这些结果证明接线和程序行为，不证明判官视觉判断或新成片质量。

代码已写入主线与 Agent 运行工作树，新章节进程自然加载；不为本修复中断在途章节。未提交或推送。
