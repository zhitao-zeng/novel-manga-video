# 自动诊断、修复与经验复用

当前运行方式（2026-10-07后续确认）：正常生产采用 main 的 `standard` 批量路径，
Agent 使用独立的 `batch_review` 队列。以下早期章节宿主策略保留作为历史记录。

审修接口更新：每轮写`input/current-task.json`，仅列当前任务及实际权限、素材和证据
入口；完整状态在`input/current-status.json`，历史错误不再冒充首拍目标。check/apply
共享输入范围、剩余额度与风险参数校验；resume不能夹带新修改。编译错误区分真正
重分段与联动片段越界，并列出变化字段。宿主源码只读供Agent定位程序问题。
连续两轮没有输出文件变化和宿主工具交接时，可按既有配置回退一次Qwen，保留时间
及拍摄计数。旧失败仅在当前问题和权限仍匹配时恢复一次，不因历史报错扩大重试。

- 批量准备调用原生规划、选定素材和H3翻译；现有剧本直接复用，失败留下明确回执，
  不在生产进程启动Agent。图片等待可恢复，失败回执在实际输入变化后才重新准备。
- 已准备片段形成约100段的库存。生成批次只选当前就绪章节，`workers=0`展开片段，
  由既有6路H3上限控制实际请求。只生成缺失首拍，保留已有视频和全部实际拍摄计数。
- 准备完成、失败和成片审查分开。Agent只消费实际视频或明确的准备异常，独立状态
  位于`production/agent-review/state.json`；原会话、剩余预算和修复起点保留。
- 审修按文字工作派发，运行中的宿主工具不占文字名额，等待中的宿主保留原章节锁；
  活跃宿主总数受100任务池约束，真实模型请求仍共用DS8/Qwen4。缺首拍输入的修复
  优先于成片审修，不再等待视频库存达到某个下限才开始修输入。修好的首拍输入交回
  标准准备/生成，原会话与剩余预算保留。模型因拒绝切到Qwen后仍保持该回退。
- H3排队时首拍先于补拍，同类请求按原先顺序执行；已取得槽位的任务正常结束。
  `text_capacity`分开报告文字宿主与后台工具宿主，不能把宿主数当成实际模型请求数。
- `batch_pipeline.first_complete`表示首拍齐全，`accepted`表示正式验收。等待图片和
  活跃审修都算未结束；无可自动推进工作但仍有未解决问题时写`blocked`，不写完成。

2026-10-07按用户目标改为动态供料：保留100个待推进任务，完成或明确失败后补位；
素材齐全的新任务可替换池内仍在等图的任务。首次生产最多12个宿主，审修最多8个，
两条队列独立调度；实际请求仍共用DS8、Qwen4和H3共6个槽位。初产宿主执行固定步骤，
到语义异常或成片审修入口保存状态并让出名额，审修取得自己的名额后继续。

等待批量素材的章节不占生产宿主。只有仍由存活批量任务负责的缺图才进入等待；
批量任务已失败或退出，缺图交回有界准备处理，不永久滞留。共享模型、图片与H3资源
排队写入各章`resource-waits.jsonl`，执行预算扣除等待时间，多线程重叠等待按墙钟
区间合并，不重复加回。规划内部重试、分批修正和压缩同样按活动时间计费。
图片取消600/1200秒的整体子进程墙钟截断，保留单次请求/轮询超时及既有重试限制。
当前服务配置单次图片请求/轮询上限3600秒；影片规划目标90秒、硬上限120秒保持原值。
监控优先看可拍队列、H3空档与实际视频产量；100个排队任务不表示100个模型请求并发。

当前用户确认的边界是`production_mode=pipeline_review`：固定流水线生产，成片由Agent
审修。拍摄前发现的明确语义或参考图内容错误也可进入定点审修；缺图、普通规划和翻译
格式错误由固定步骤处理。普通规划器不自动接手对白改写；Agent可通过有原文依据的
`input.shots[].turns`直接修词、说话人和内心独白，只有明确请求才整集重编。
前置失败和成片失败分开记录；生成任务编号不能代替实际视频。中断的前置修复续跑后
仍需完成完整准备，修改对白不能重置剪切、时长或拍摄预算。

此模式的共享memory只收录审修问题，包括拍摄前的语义修复，保存在`.production-memory/`的独立JSON
与Markdown案例中，`index.md`按问题类型列出结果。并行更新索引使用文件锁；没有新增
总结模型。只有正式finish通过才标accepted，失败尝试仍标unresolved。后续Agent只
获取相关的少量案例，不能将未验证尝试当成成功规则。

正常章节仍走一次编稿、准备、H3生成和验收；异常才进入生产Agent。每次修复回合由宿主读取当前剧本、媒体、正式验收、输入修复和最终发布阻塞，给出具体失败层与可执行动作。过期的导出报告不能覆盖已经通过的当前结果。

`<run>/recovery-diagnosis.json` 保存本轮诊断。原书输出目录的 `.production-memory/<run-name>.json` 保存问题类型、实际尝试、接受的片段和最终结果；按同类问题取最多4条经验进入后续回合。未解决的尝试明确标为未解决，只有宿主正式finish通过才记录整集accepted。通用经验随 `skills/episode-production/references/case-lessons.md` 进入每个沙箱，不依赖这次聊天。

默认处理：

| 失败证据 | 自动处理入口 |
| --- | --- |
| DS明确拒绝，或连续两轮只总结而没有有效工具交接 | 配置`refusal_fallback`后，最多一次切到Qwen Flash Next，新会话继续已有产物；保留原操作预算与拍摄记录。已阻塞的总结循环仅在有两次会话证据、剩余时间且未切换过时自动接续一次。JSON模型请求的明确拒绝也在原请求期限内回退一次。 |
| 草稿缺图却无法通过修复参数检查 | 尚未采用的草稿按草稿片段核验补图请求，与apply共用无副作用的参数检查；不要求先有已采用计划。CLI文件是位置参数：`python3 /work/tools/episode.py check output/repair.json`。 |
| 对白超过片长能容纳的数量 | source草稿采用前检查每秒最多6个汉字，建议4–5字；采用后可用input的`shots[].turn_texts`缩写过满对白，逐句保留说话人、顺序和方式，独立核对关键含义。script定稿仍不允许这项改写。 |
| 对白语义、归属或心声方式错误 | Agent结合原文提交`shots[].turns`定点修改；检查只覆盖改动及依赖镜头，重新翻译并验证最终绑定。受影响镜头的旧说话人契约随修复发布而撤销，其他镜头的记录保留。误报可用`recheck_input`独立复核；同一输入只复核一次。 |
| 同音字、人名ASR拼写差异 | 全句实际音节一致时不按漏对白失败，保留原始识别和提示；无声、缺有意义的命令、长段漏说及新增话语继续检查。 |
| 笑声、短感叹声 | 重复笑声音节记提示；“啊”等非词汇感叹在有声音证据时可提示通过。“杀”等剧情命令仍须检测。 |
| 旧语音规则误报 | 对保留的ASR和音量重新计算，不需要先重拍。声音以外的缺陷保留。 |
| 旧角色登记与当前造型冲突 | 以原文和实际选用的阶段图判断；不把旧基础性别字段强加给新阶段。轻微衣纹、色差和风格差异记subtle。关键动作错人、缺角色和严重画面错误仍失败。 |
| 角色已存在却被请求为新角色 | 归入当前角色的阶段造型，并保留可续跑的候选与素材。 |
| 缺失或损坏参考图 | 不把坏图片送给模型；优先使用有效视图，记录缺失后由现有素材工具生成并绑定。 |
| 源镜头被相邻片段共用 | 自动补齐直接关联范围，保留原剪切与次数限制；不同场景等语义问题仍由Agent据原文修正。 |
| 普通验收通过而最终发布未通过 | 最终发布明确指出的片段也进入修复权限及证据，不再给出空操作列表。 |

本轮规则不会自行扩大影片总拍摄预算。已有额度继续计数，受用户本轮授权的一次条件补拍必须先完成输入检查。无效同操作不会无限循环；真实缺原文、没有剩余额度或工具尚不能表达的修法会留下可定位原因。

修复进展按实际结果计数：发布的输入修改、新增素材和已通过复核的保留操作才算收益。
失败内容换了一种说法、重新提交已耗尽的操作、重复领取已完成输入回执，都不能刷新
无进展计数。连续两次没有实际成果时停止当前会话，跨调度切片也保留这个计数；一次
操作修好部分片段而另一些失败，仍保留并继续已修好的部分。

源文检查中的 `problems` 只应含事实矛盾。初审否定或同时给出肯定结论和问题列表时，
宿主对照原文及本次修改独立确认一次，只保留有真实原文引句的具体矛盾。肯定说明
不能被当作返工理由；服务失败或无效引用也不能当作通过。初审及确认结果随输入回执
保存。旧版在 source 步骤拒绝的最后候选，可由调度自动恢复一次，使用原候选及剩余
活动时间；修订/续跑计数、实际拍摄次数和其他步骤的失败都不重置。

2026-10-07任务池长期运行修正：任务从首次生产转为审修后，保留所有旧成员会使100个
位置最终被审修占满。现在每条队列按其宿主容量补足可执行任务；只换出未运行的超额

批量素材入口必须显式传`--endpoint deepseek`或`flashnext`，整批及其子进程统一绑定
设计、看图与审核接口；启动先检查接口可达，避免一边付费出图一边向停用接口审核。

再生成。恢复次数、旧失败和pending状态在派发前保存；重启继续未完成审核，不把
文件存在当成审核成功，不重新发放恢复次数。素材报告区分image_exists与审核结果。

用户要求首次生成优先时，本批启用 `agent.first_pass_priority=true`。按每个视频片段
是否已有实际文件分类，未拍片段所在的章节（包括只拍了一部分、带旧修复标签的章节）
使用12个首次生产宿主。有活动或可执行首次任务时，不派发新的成片返工宿主；旧操作
自然完成。首次片段全部有视频后，章节才交给成片审查/返工队列。只有等待素材或已经
明确阻塞的首次任务时，其他可执行工作可以使用空闲资源，不能把阻塞当作首次已完成。

首次宿主仍以固定pipeline生成，确定的输入语义错误才调用Agent；Agent只处理未拍
片段的输入，不能重拍已有视频或启动整集审查。已有片段的音频补录、复核和合成延后，
缺段的素材等待不受已拍片段的缺失素材影响。生成器在实际提交处禁止首次任务夹带
已有视频重拍。保存的旧视频标为待审，不因首次齐全就宣称验收通过。无效修复仍受
两次无进展限制，已有拍摄预算不变。

首次优先模式下，模型分配是容量选择，不是永久绑定。若首拍宿主已结束当前切片，
首选模型满额而另一已分配模型有空位，普通待续跑任务可携带原会话直接续跑；首选
模型有空位时保留原分配。运行中的宿主、已接收/执行中的操作以及明确 `model_switch`
回退任务不搬移。CLI显式指定本次模型并使用原会话ID，不重读建库、不重置无进展
计数、剩余时间、输入次数或视频次数。实际曾出现Qwen4个宿主满额、二十多项普通
首拍队列绑定Qwen、DS8个章节位置闲置的情况；调度按上述条件自动消除这种空闲。
